# TypeScript Native Harness 核心

本包提供与宿主无关的 Native 执行状态机、端口和可恢复账本。源码不依赖 DSH、Studio、文件系统或 Python。Node SQLite 实现在相邻 Harness 包的 `src/native/sqlite-store.mjs`。

当前实现包含模型与工具执行闭环、独立的模型错误和供应商重试预算、并行只读工具、串行写工具、取消与暂停、审批、验证反馈，以及执行意图、回执、状态和事件的原子提交。完整迁移和 Studio 接入仍在进行，见根目录迁移说明。

同一作用域和会话只允许一个活动轮次；新轮次通过会话 head 的原子比较继承已结束历史。工具调用与结果保持配对，未提交结果闭合为未知观察，历史本身不会触发执行。导入调用身份稳定，供应商重用调用 ID 时生成新身份。`replayToolIds` 单独携带协议 ID 映射，模型端口须应用该映射，保留私有原始回放。

`configure()` 显式解析配置；`NativeKernel.start()` 创建具备固定配置摘要的运行；`runUntilIdle()` 推进到终态、暂停、待审批或重试等待点。宿主提供模型和工具端口，按需提供其他端口。端口不接收账本写权限，凭据必须留在宿主的配置解析层。

运行身份包含作用域、会话、轮次、Build 和任务链。账本的租约与 fence 拒绝过期执行者；状态版本比较防止丢失更新。副作用必须先提交 prepared 意图，再 claim 为 running 后执行。回执、后续状态和事件同批提交。重新接管时，已 claim 但缺少回执的操作进入结果未知状态，不会调用普通执行器重放。

取消是持久命令，优先于最终完成提交。工具超时或抛错可能发生在外部状态已经变化之后，因此按结果未知处理；迟到结果不能改写账本。租约不能保证外部系统只执行一次，适配器仍需使用外部幂等键或观察核对机制。

`verified` 要求当前候选、契约版本、上下文、环境及 verifier 身份匹配，并且所有必需验收项都具有合格的非模型辅助证据。缺失证据保持 `unverified`，部分通过保留 `partial`。终态提交前重新观察工作区；变更会使旧报告失效。没有可交付文本的耗尽运行进入 `failed`，未知副作用进入 `interrupted`。

事件序号与投影确认游标支持有序重放。跨数据库投影还需消费方按照事件身份幂等写入；单独更新游标不能消除“写入成功、确认前崩溃”的重复窗口。供应商私有回放只存于运行历史，不进入公开事件。

在仓库根目录执行 `node scripts/build-native-harness.mjs` 构建，再执行 `node --test packages/agentkit-harness-core/test/*.test.mjs` 验证核心。测试包含内存和 SQLite、事务回滚、数据库重开、真实进程退出、取消和迟到回执。项目最低 Node 版本的独立验证记录在迁移说明中。
