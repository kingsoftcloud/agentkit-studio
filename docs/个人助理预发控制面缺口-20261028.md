# 个人助理预发控制面缺口（2026-10-28）

Studio 侧已实现「零配置」：Host 用云账号凭据发现个人助理实例、复用已有 AK、失效时自动重新获取，
插件页面不再需要填网关/实例/AK。真实链路已验证：发现实例 → 网关签发 43 字符短时票据 → wss 握手成功。

以下两项是预发控制面（不是 Studio/插件）的缺口，导致「凭证丢失自动重新生成」和「没有实例时创建」
在预发不可用；线上接口正常时 Studio 代码路径不需要改动。

## 1. CreateAgentApiKey 全局 500

- 请求：`POST /?Action=CreateAgentApiKey`（AICP 内网，aws4 签名，`Region=cn-beijing-6`）
- 现象：对个人助理 `ar-20261026143422-edd563a1` 与普通 harness Agent 均返回
  `200 {"Code":500,"Message":"服务内部处理失败，请稍后重试。"}`；缺 `AgentId` 时返回 422
  「AgentId 为必填项」，说明动作存在、服务端创建逻辑异常。
- 影响：Studio 无法为新实例或其它子账号生成 AK，只能复用已有绑定；页面显示
  「云端暂时无法获取连接凭证，可以重新获取」。

## 2. CreateAgent 不认个人助理 Framework

- 请求：`POST /?Action=CreateAgent`，`DeploymentType=ManagedRuntime`，
  `ManagedRuntimeConfig.RuntimeName=personal-assistant`。
- 现象：
  - `Framework=personal-assistant` → `422 Framework 格式不正确`；
  - `Framework=harness`（对照）→ `400 ManagedRuntimeConfig.RuntimeName 必须与 Framework 一致`。
- 即预发控制面当前没有注册个人助理 Framework/运行时版本，无法通过 API 新建实例；
  既有实例（0.1.6 时期创建）仍可正常使用。
- 影响：没有实例的子账号在插件里点「创建个人助理」会得到明确提示，而不是静默失败。

## 复现

```bash
# 1) 凭证
node /tmp/create-pa-instance.mjs   # 三种 Framework 变体，见上
# 2) 票据（用已恢复 AK）
node /tmp/live-ticket-ws.mjs       # {"open":true}
```
