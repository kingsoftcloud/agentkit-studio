# Native 交付复核

参考为 KsADK `355059d78e47ed764bbdb3606304cdf34e9838a3` 的
`delivery_review.py`、`delivery_review_contract.py`、`model_request.py`、
`verification_runtime.py`，以及 `test_delivery_review.py` 和 `test_delivery_review_sources.py`。
这是原 Native 的可选模型诊断策略，不替代 Host 的确定性验收。

核心支持可选 `deliveryReviewPolicy`。Studio 可在 Revision/Frozen Build 的
`spec.execution.deliveryReviewPolicy` 中固定它，例如：

```json
{
  "pathSuffixes": [".ts", ".js"],
  "maxRounds": 2,
  "maxReadRounds": 2,
  "reviewUnknownPaths": true
}
```

默认轮数分别为 2，允许范围为复核 1–4、源码读取 0–4。策略省略时保持原配置和行为。
Host 在生成绑定摘要前固定默认值；恢复使用原策略，不能用当前配置替换原运行的权限。
启用后保留内部控制名 `submit_delivery_review`，它不执行工具，也不计工具调用。

只有实际捕获了相关工作区变更、候选因缺失或不完整验收证据而未被接受、存在获准修复
工具并保留原模型/工具/修复预算，才启动复核。同一目标、工作区内容和交付物只复核一次；
变更后可以再次复核，仍受轮数上限限制。工作区不可观察或仅执行只读任务不会触发复核。

复核只暴露 Host 已声明的工作区读取、搜索和产物读取工具，并保留原目标允许列表、
工作区边界、审批和执行账本。读取在模型调用前准入，计费后仍可执行已经准入的读取。
混合写入、超出读取轮数或伪造控制参数不会产生副作用。诊断严格校验需求、实现证据、
验证证据和具体问题，不接受额外的通过声明或验收字段。

复核文字、流和截断续接仅用于私有诊断。截断片段绑定原 Host 效果身份和摘要，保留在
同一 SQLite 账本；不会拼到实施答案中，也不会压缩进公开任务历史。复核上下文放不下时
返回复核不可用并保留原候选。真正的源码调用与回执仍可投递、恢复，私有模型协议不继承
到后续会话。公开会话记录模型用量，不显示诊断文字。

发现问题后，核心把明确标为不可信的建议交回实施模型，在原权限和预算内修复并重新
验收。干净、无效或不可用的复核都保留原候选并重新走验收；任何建议都不能使缺失的
人工、语义或确定性证据变成通过。取消和目标变更优先于复核，陈旧主体的建议不能修复
新主体。未知修复副作用仍停止核对，不自动重发。

定向验证覆盖内存/SQLite、实际文件修复、模型和工具预算、私有续接重开、源码准入、
公开用量及冷投递去重；四个实际 SIGKILL 边界覆盖复核等待、续接、修复写入后回执缺失
和取消。Revision/Frozen 共用生产 Host 的 HTTP 模型与真实文件链路另有专项验证。
这些记录不替代全部产品入口、真实线上模型、其他平台、最终安装及默认切换验收。
