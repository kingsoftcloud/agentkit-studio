# Native 工具错误诊断恢复

参考固定为 KsADK `355059d78e47ed764bbdb3606304cdf34e9838a3` 的
`native/tool_error_recovery.py`、`tool_error_streak.py`、`observed_progress.py`
和 `tests/harness/native/test_tool_error_recovery.py`。这属于原 Native 的正式执行路径。

核心配置新增可选 `toolErrorRecoveryPolicy: "diagnose-before-repeat/v1"` 和
`toolErrorRecoveryModelCalls`。后者只接受 1–10；省略或 null 表示没有额外诊断调用上限，
仍受原运行预算约束。原配置省略这些字段时保持旧配置和绑定摘要，以及原六次错误停止行为。
新接纳的 Studio Revision、Frozen Build 和共用托管 Host 启用策略；恢复时保留原配置。
Studio 可从 `spec.execution.toolErrorRecoveryModelCalls` 固定额外上限，默认不另设上限。

同一目标和工作区观察下，六次模型决策产生相同确定工具错误后，核心暂停重复动作，
要求读取实际状态或采用其他获准方法。单批工具只累计一次错误决策。只读查询的失败身份
包含参数摘要，写入和浏览器动作不能靠更换参数规避限制。浏览器使用锁定端口的语义观察
摘要；其他工具比较内容和媒体块，工具正文中的权限或观察声明不产生授权。

原失败动作只有获得新的成功观察后，才能在后续模型决策进行一次修正尝试。同一批中的
读取不能批准尚未看到结果的写入。修正尝试与原执行意图同时持久化，仍受原审批、取消、
工作区和预算限制。尝试失败后，新的读取也不产生第二次尝试；其他获准动作仍可执行。
诊断或工具成功不构成任务验收，确定性 verifier 保持独立。

成功观察按全局内容或可信语义摘要去重，最多保留 2048 个指纹。错误前见过的同一观察
不能再次用来许可修正。普通读取和其他写入不重置诊断预算；空响应、上下文压缩和摘要
重试同样消耗原模型额度。压缩连续性记录保留静态诊断事实，模型调用前检查实际剩余额度。
更改用户目标会解除旧目标的诊断限制，单纯工作区变化不会解除已激活的限制。

实际进程强杀测试覆盖诊断开始、修正意图落盘、写入后未提交回执和取消窗口。
前两种边界恢复原尝试；写入结果未知时停止且不重复写；取消发生在执行前则不执行。
同时覆盖真实 SQLite 重开、原审批恢复、Revision/Frozen 共用 Host 的 HTTP 模型、
实际文件读取和修正写入。具体命令、最终计数和包证据保存在本次迁移验收记录中。
这些专项验证不代表全部能力、线上模型、所有产品入口或默认切换已完成。
