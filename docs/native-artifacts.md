# Native 工具结果归档

当前实现覆盖 **TS 核心、Node 存储及共用 Studio Native Host 的归档执行链路**，迁移尚未完成。
新建 Native 运行及其子任务已绑定独立作用域的归档端口；旧的未标记运行保持原配置。
动态来源读取预算及完整产品验收仍需闭环，不能据此声称所有入口已完成无损迁移。

核心配置显式绑定 `artifactPolicy: "runtime-artifacts/v1"`，并加入
`artifactToolDefinitions()` 返回的三项原样定义。策略、工具定义和字节上限随配置封存；
缺少定义、修改保留定义或结果预算低于 1024 字节会拒绝配置。没有此策略的已有配置
保持原执行方式。共用 Host 对已经选择 Native 的新运行启用此策略，并保留恢复时的原策略；
当前没有修改产品默认执行引擎。

## 回执与模型视图

原工具调用仍在已有持久执行意图内执行。工具返回后，Kernel 按完整模型结果视图的
UTF-8 大小判断是否归档，再一起提交回执、引用和状态。完整原始 `content` 留在回执中，
模型收到受字节上限约束的独立 `context`，包括真实执行状态、预览、归档可用性和引用。
设置 `resultArchivePolicy: "archived-model-view/v4"` 的成功结果即使较小也会归档。

当宿主提供独立模型视图时，可读归档保存该视图，不能通过 ArtifactRead 暴露被宿主
隐藏的原始事实。额外上下文和媒体超过上限时也进入归档；省略媒体的反馈明确说明
本次响应没有观察这些媒体。归档失败不把已成功写入改成失败，也不要求重新执行副作用。
审批和结果未知仍保留原控制状态，不授予新归档引用。

运行时验证存储返回的内容摘要、字节数和媒体类型后才授予引用。工具回调提供的
`artifactRefs` 不直接成为权限。Kernel 在封存策略下发送 `resultGovernance`；真实账本
授权器核对该标记，本地/E2B 命令端口才返回完整保留输出供中央归档，防止先截断再归档。
旧运行仍使用原命令归档；已继承的有效引用可通过同一作用域的只读后备存储读取。
仅主存储明确报告引用不存在时才查后备，损坏、摘要或作用域错误不会被掩盖。
完整回执、模型视图和用于进展比较的内容身份分别保存，
同样内容产生新 URI 不算新增来源进展。

## 读取权限与分页

- `ArtifactRead` 只接受当前 Run 已提交引用，或同一会话父 Run 实际继承的引用。
  模型文字、用户粘贴的 URI 和存储中存在的文件均不能授权。偏移以 Unicode 码点计算，
  返回 `next_offset` 继续读取，字节上限同时计算 JSON 转义和模型结果外框。
- `ArtifactSearch` 对最多 8 个已授予 URI 做区分大小写的字面搜索。搜索前检查所有引用，
  不调用存储的全目录搜索；每个归档扫描最多约 1 MiB，最多返回 16 条。扫描、结果数或
  输出大小造成省略时，`complete` 为 `false`。当前搜索对象是归档文本，尚未加入原参考
  captured-source 格式的正文解码、源路径和源行号。
- `ArtifactList` 分页列出已授予清单，最多请求 8 项，按实际字节上限继续缩小页面。
  上下文连续性只携带最近 8 项的紧凑引用和总数，完整清单通过该工具读取。

这三项在 Kernel 内执行，仍经过正常工具准入、预算、持久意图和前置 Hook。
只有当前声明批次之前已经提交的引用可以读取；同批另一工具尚未提交的归档不能授予权限。

子任务有自己的配置、工具预算、存储作用域与已授予清单。父运行不会因子任务读到归档
而获得跨作用域读取权限；保留工具不交给外部 DSH registry 执行。没有业务工具且工具
预算为零的角色不会因为安装了三个保留定义而得到新的调用预算。

## 目录投影与导航

可信 `list_workspace_files` 可绑定 `studio-directory-observation/v1`、`v2` 或 `v3`；
共用 Host 的新运行使用 v3。模型最多看到 100 个有序路径，UTF-8 反馈另受结果上限和
归档外框预留约束。v2/v3 的递归视图补充已实际返回的直接子目录；v3 同时描述 path、
glob、递归范围和浅层空目录。元数据与完整授权条目保存在归档，不另读文件系统。

持久导航只来自当前目标下已提交、身份匹配的成功目录回执。完整授权视图与受限投影
分别保留，Host 后置策略隐藏的名称不会从归档或导航泄露。导航可累积已见子目录，
模型连续性引用有大小限制，明确不证明当前存在、新鲜度或完整树覆盖。

纯 TS `captured-source-artifact/v1` 编解码器已加入，保留原始正文、路径、行号、Unicode
换行与大整数，并拒绝重复键和浮点行号；目前只是经过验证的格式基础，尚未将完整
requested-source 捕获、分页搜索和动态容量接入生产读取链路。
