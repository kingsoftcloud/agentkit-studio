# 三运行时 WPS 渠道验收

使用经 IAM 核验的子账号，通过 KOP 和 Studio 部署编排创建独立 DSH Native、Codex Agent。
两者使用共享镜像 `0.0.1-94abbbd`、`glm-5.3-flash` 和 20 GiB 持久卷。冻结包只绑定模型
与验收知识库，不包含记忆库、MCP、Skill 或其他插件；用户输入不包含系统前缀或知识答案。

## 真实路径

1. 通过 Studio 渠道模块创建云端渠道，确认 `ConnectorWorkspaceId` 为空。同一授权测试
   WPS 应用依次绑定两个 Agent，任一时刻只有一个配置启用，没有多个连接抢占事件。
2. 用户侧通过 WPS 官方 deeplink 发出消息，读取实际历史核对发送者、会话和配对码。
   配对码与服务端哈希一致后才审批，不预置或猜测用户绑定。WPS 入站的应用用户 ID
   不等于客户端内部用户 ID。
3. DSH 的审批经 Studio Node 模块完成；Codex 的审批从真实 DSH Web 页面
   “运行中心 → Channels → 配对请求 → 通过”完成。数据库回读的批准人均为已核验子账号。
4. 执行阶段停止验收用的本地 Host。知识库问题、记住代号、仅询问上一轮代号三条真实
   WPS 入站消息，分别完成知识库盲测和历史续聊。回复均带冻结 system prompt 的前缀。
5. 为实际入站自动创建的 binding 设置单次计划，任务询问同一个知识库问题。Server
   自动执行，Channel Worker 主动发送，真实 WPS 历史与 Server `ResultText` 完全一致。

| 运行时 | 配对与自动绑定 | 同会话续聊 | 知识库盲测 | 定时结果真实送达 |
| --- | --- | --- | --- | --- |
| AgentKit Harness | 上一批次通过 | 上一批次通过 | 独立云端对话已通过 | 上一批次通过（算术任务） |
| DSH Native | 通过 | 通过 | 入站和计划均通过 | 通过 |
| Codex | 通过，含真实页面审批 | 通过 | 入站和计划均通过 | 通过 |

DSH 和 Codex 每个计划分别只有一个 occurrence，`Attempt=1`；状态为 `succeeded` /
`delivered`，对应 outbox 的 `retry_count=0`。各自只有一个匹配的 outbound audit 和一条
完全匹配的真实 WPS 消息。Server 的交接/查询次数不能当作平台重复发送次数。
这些单次结果不构成网络故障下的 exactly-once 保证，确认不明仍按既有规则不自动重发。

验收后停用并软删除两条测试计划，经 KOP 删除两个独立 Agent，确认 Namespace、PVC 和 PV
均已回收。专属私有运行包核对归属后删除，下载返回 404；测试 Channel 配置、凭证、配对、
binding、outbox 和消息审计行已清理。本地临时配置已恢复，真实 WPS 应用和消息保留，
日常 Host 未改动。最终账单结算不在本次证明范围。
