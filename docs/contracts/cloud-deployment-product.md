# 云端部署产品与镜像维护边界

目标是本地创建的 DSH Native、Codex、AgentKit Harness 使用同一套部署交互与管理入口。
当前 Node 传输、Server 镜像目录和运行中心的冻结版本部署已接通；页面创建、状态与日志已有
真实预发证据，Harness 的页面创建至就绪、流式回复和删除已通过；详见[验收记录](deployed-resource-acceptance-2026-10-08.md#运行中心部署页面验收)。Agent 云端标签及原生会话已接入，Harness 有真实子账号创建与浏览器对话证据；Harness 原实例升级回滚已有[页面验收](deployment-rollout-acceptance-2026-10-08.md)，三种运行时的[容器重建后续聊](cloud-storage-acceptance-2026-10-09.md)已实测，完整资源组合仍在联调。

## 页面操作

运行中心按三个步骤组织：选择本地 Agent，选择成功的构建版本或构建当前版本，检查部署配置后确认创建。
默认选中最新成功构建；构建历史收起，展开后可切换版本、本地调试或下载产物。冻结版本代表构建时的
提示词、模型和资源绑定，不会因为后续编辑自动改变。快速切换目标时只接纳最新目标的详情响应。

CPU 与内存合并为实例规格，默认 2 核 4 GB。通用规格按 1:2 配对，支持 1/2/4/8/16 核；
需要时可选 1:4、1:8 的更多内存规格。Node Host 同样校验这些配比，未指定内存时取 CPU 的两倍。
既有部署保持原规格，升级和回滚仍复用当前实例。更改版本或规格后必须重新检查，旧检查结果不能用于创建。

部署记录默认只显示当前 Agent 的未删除实例；全部 Agent 和已删除记录可显式选择，每页最多五条，
按创建时间倒序。其他 Agent 的未知创建结果等待处理状态仍有提示，不会因过滤而默默消失。
展开详情查看云端标识、构建和存储；删除须二次确认。创建结果未知只提供核对入口，不提供重复创建。
构建和部署操作记录按需展开。[页面验收记录](studio-ui-acceptance-2026-10-09.md)列出真实浏览器结果，
页面交互验证不替代各运行时、资源组合和云端规格的真实部署验收。

## 身份与生命周期

Studio Node Host 使用用户配置的 AK/SK 对 KOP Action 签名。**签名成功不代表子账号
操作人已传递。** `X-Ksc-Account-Id` 表示资源所属主账号，`X-Ksc-User-uuid` 表示子账号
操作人；Server 读取后者，再传入创建订单的 `user_uuid`，最终创建回调将其持久化。
AK 同时用于签名及 KOP 公共参数 `Accesskey`；SK 仅用于计算签名，不放入请求正文。

2026-10-08 的独立预发测试确实请求了 AICP 内网 KOP Action 入口，但未发送
`X-Ksc-User-uuid`，首次失败 Agent 的 `Basic.Creator` 为空。同一套凭证的 IAM 只读核验
在默认账号密钥列表中命中当前 AK，`UserName` 为空；完整子用户密钥列表未命中，表明该
测试使用主账号密钥，不能从中推导其他子用户身份。模型凭证映射修复避开了自动申请 AICP
Key，不是子账号身份修复。详见[部署传输边界](deployment-transport.md)。

旧 KsADK 客户端已有 IAM 身份解析和身份 Header 传递。新版 Node 部署客户端现已补齐
`inspectIdentity()`：用当前签名凭证调用 IAM `ListAccessKeys`，只匹配当前 AK；有子用户名
时再调用 `GetUser` 核对用户名、UUID 和 KRN 中的账号归属。部分 IAM 环境默认返回所属账号的密钥；当前 AK 未命中时通过 `ListAllUserAccessKeys` 精确匹配用户名，再用带 `UserName` 的 `ListAccessKeys` 核验当前 AK 为 Active。该回退需要对应 IAM 查询权限；缺失、重复、截断或不一致都不能当作主账号或猜测操作人。
`CreateAgentProduct`、`UpdateAgent`、`DeleteAgent` 发送前执行此检查，已验证的子账号
UUID 和主账号 ID 加入签名 Header；与配置账号不一致或身份查询失败时不发送写请求。
主账号仍可被只读识别，但 Studio 部署编排在检查和上传前拒绝主账号创建，不生成子账号 UUID，也不改变平台自动申请 AICP Key 的限制。
只读详情、实例和日志查询不依赖 IAM，身份服务异常时仍可诊断既有部署。

检查结果短期缓存在 Node 内存，凭证或会话令牌变化会重新验证；不存储原始 IAM 响应，
不接受浏览器传入的操作人 UUID。`make cloud-identity` 可只读检查当前配置；
`node scripts/check-cloud-identity.mjs --require-subaccount` 在主账号情形返回非零状态。
真实主账号识别已验证；子账号 Header、签名、缓存失效及失败拒绝已有回归测试。
随后使用独立子账号凭证完成创建，`GetAgent.Basic.Creator` 已与 IAM 用户名一致，证明创建者已传递至可读取的 Agent 记录。随后又对同一记录做只读数据库核对，创建者子账号 UUID 与 IAM 一致；两个子账号间的权限隔离仍未验收。

三种运行时都走 `CreateAgentProduct(DeploymentType=Container)`、`GetAgent`、
`UpdateAgent`、`ListInstances`、`GetAgentLogs` 和 `DeleteAgent`。平台尚无独立停止/启动
Action，不将删除显示为停止。MCP/Skill 等绑定冻结在运行包中，不能通过旧 ComponentConfig
更新接口假装已经同步这些绑定。

## 用户操作

当前操作为：运行中心 → 构建与部署 → 选择本地 Agent 和冻结 Build → 检查部署 → 确认创建。
Build 可由“构建当前版本”生成，也可选历史版本。区域和环境跟随设置，规格默认 2 核 4 GB，
可选 1:2、1:4、1:8 配比；确认页显示版本、运行时、镜像、资源数、操作人及当前限制。私有 KS3 桶
在设置中配置；用户无需输入 Docker 命令、镜像地址、对象路径或摘要。

`studio-deployments.mjs` 在 Node Host 中编排 IAM 核验、镜像目录解析、冻结资源凭证解析、
私有上传和 Container 创建。确认前后版本、环境、凭证作用域或资源地址变化时拒绝提交；
模型 Key 可轮换，但不能用当前默认模型替换冻结绑定。模型/MCP 凭证只在 Node 内存和平台
敏感环境变量中传递，不写部署记录或返回浏览器。平台注入 AK/SK，不把桌面长效 AK/SK
复制进容器环境；当前 Container 不保证 STS 令牌注入，需要 STS 的运行包会明确拒绝。

部署记录先于外部写入持久化，使用独立幂等键和不可变计划。上传、创建、令牌同步、删除
分别记录单次执行声明；网络中断不盲目重试。创建结果不明时按唯一部署名查询，并核对
云端 Agent ID、镜像摘要和运行包摘要后才接管。记录固定云端凭证作用域，切换 AK 或环境
后拒绝管理旧记录；仅轮换 SK 无须修改记录。未知上传结果目前需要人工核对，不提供自动重传。

状态、日志与删除在运行中心展示。网关 `/health` 成功还不足以判定可运行，必须通过
不启动模型的 Responses 鉴权探测。`GetAgent` 会掩码敏感环境变量，不能据此反复写入令牌。
首次令牌同步等待实例运行，避免与初始创建相互覆盖。若实例运行后仍明确返回运行时令牌
不匹配，可点击“修复访问配置”；该操作再次核验归属与鉴权错误，只补写访问令牌，并记录
单次修复声明。网络失败、网关拒绝或未知响应不会触发重写；修复结果不明时继续核对。
控制面为 `UPDATING` 而入口已通过探测时显示“入口可用 · 平台更新中”；只有控制面已运行且
入口验证通过才显示“就绪”。日志隐藏已知敏感值、Bearer 和 URL 访问令牌；删除与状态检查
串行，删除后确认 GetAgent 404 或平台已删除状态才记录完成。页面删除实例保留私有运行包
供审计，当前不自动清理对象；测试专属对象在实例删除后另行核验摘要并清理。

云端 Agent 标签和原生会话选择器仅加载当前凭证作用域内的部署记录，不调用历史通用 Agent 列表。进入会话及每轮执行都核对云端 ID、名称、镜像和包摘要；本地配置变化不能改变云端冻结模型。用户需重新构建部署以更换云端模型。

Node Host 调用实例的 `/v1/responses`，只发送本轮用户文本、固定模型与稳定的会话/消息标识，不发送桌面系统提示词、历史或工具定义。云端执行冻结的资源绑定；DSH 展示文本、思考、工具结果与用量。工具卡片仅作展示，不在本机重复执行。响应必须返回匹配的 Agent/Build 身份；取消同时中断连接并对已核验的响应发送取消请求。

删除或切换凭证后保留历史展示用的 preset，但每次实际运行仍重新检查当前作用域、部署状态和远端身份。桌面 Host 恢复与云端实例重建的持久化是不同验收项；后者的三种运行时模型对话已通过独立验证，详见[持久化验收](cloud-storage-acceptance-2026-10-09.md)；Harness 升级回滚结果见上述页面验收。

升级/回滚已接入原实例的 `UpdateAgent`，目标镜像须支持运行身份探测。切换期间暂停新对话，成功版本和历史冻结包分开保存，旧会话不会静默跟随升级。完整操作与失败恢复规则见[云端版本升级与回滚](deployment-rollouts.md)。

## 对话持久化

新部署默认选择 20 GiB 持久化存储，也可选择更大容量或明确选择临时存储。确认页显示容量
与按天计费方式，价格以平台计费为准。Host 先核对 Server 的
`Capabilities.ContainerStorage`（`agentengine.container-storage/v1`），再上传或创建；
缺少声明的旧环境不会被当作已支持。声明来自 Server 实现，不来自镜像目录的可编辑配置。

三种运行时共用显式 `Storage={MountPath: /var/lib/agentkit, SizeGi: ...}`，固定一个实例。
Server 保留该配置至现有订单和 Runtime Service，复用持久卷挂载与单实例重建策略。
就绪检查和每次对话连接都回读存储配置；若目录或容量与创建意图不符，会阻止对话并提示核对，
仍可清理测试实例。平台接受参数不等于实际重建后恢复成功，逐项结果见[真实验收](cloud-storage-acceptance-2026-10-09.md)。

已有临时实例不会自动迁移。升级沿用原部署容量；不同冻结包以 ZIP 摘要分目录保存历史。
这不是跨版本接续、跨副本共享或运行中任务的自动恢复，也不提供存储扩容和备份功能。
删除前需备份需要保留的数据；删除控制面 Agent 与底层卷回收分别核验。

## 资源绑定的迁移范围

| 绑定类型 | 冻结及云端使用方式 | 当前限制 |
| --- | --- | --- |
| MCP | 固定服务地址、协议配置与凭证引用，部署时注入对应凭证 | 云端网络、可信证书及资源权限必须可用；本机进程和 localhost 服务不能直接迁移 |
| Skill / Skill Space | 下载并打包实际 Skill 目录，云端按冻结文件加载 | 脚本所需依赖及命令沙箱须在目标宿主可用；Codex 云端命令沙箱尚未验收通过 |
| 知识库 / 记忆库 | 保留资源 ID、区域、端点和绑定配置，由云端调用原资源 | 不复制整个数据集；平台注入的身份必须具有资源权限，三种运行时独立知识库盲测已通过，完整资源组合仍待验收，见[资源隔离记录](cloud-resource-isolation-2026-10-09.md) |
| 资源插件 | 当前支持知识库、记忆库和 Skill Space 对应的绑定插件 | 不能据此推导支持任意桌面插件 |
| 其他 DSH / Codex 扩展插件 | 导出明确返回 `PORTABLE_PLUGIN_UNSUPPORTED` | 不会静默丢弃绑定，也不复制本机插件安装目录、登录会话或授权状态 |

本地编辑绑定后，需生成新的冻结运行包并升级已有部署；云端不会自动读取桌面最新配置。
运行包可离开桌面独立运行，但“绑定已保留”与“每个运行时实际调用成功”分别验收。
逐项结果见[真实资源验收](deployed-resource-acceptance-2026-10-08.md)，不能将合同测试或某一运行时的结果扩大为全部组合已通过。

## 一套共享镜像

`agentengine-images/deploy/studio-runtime` 维护一套共享镜像，内置固定 Node、DSH、Studio
和官方 Codex npm CLI。冻结包里的运行时字段选择对应适配器。每个 Agent 单独上传私有包，
无需重建镜像。Skill 的额外系统依赖需要另行声明并纳入受控镜像变体，不能在启动时任意安装。

发布流程：更新源码锁与依赖版本 → 构建不可变标签 → 验证三种运行时及沙箱 → 推送镜像仓库
并记录 digest → 预发真实资源/生命周期验收 → 发布环境与区域对应的推荐版本。
已有部署继续固定原镜像和 Build，不随推荐版本改变而静默升级。不覆盖同名版本标签。

## 复用 Server 数据库配置

Server 已有 `client_bootstrap_configs` 表与 `GetClientBootstrapConfig`，可以按产品、客户端、
运行时、环境和区域下发配置。Studio 使用独立产品范围的镜像目录，复用此配置能力，
不硬编码最新标签，也不改变其他产品的默认镜像。镜像字节在 KCR，数据库保存推荐版本、
镜像地址/digest、支持的三种运行时、运行包协议版本、兼容 Studio 版本及启停状态。

Node 部署客户端现已接入 `GetClientBootstrapConfig(Product=agentkit-studio, ClientType=studio)`，
`deployment-images.mjs` 解析 `studio.runtime.images.v1`，按三种运行时与 Studio 版本筛选。
目录仅接受固定 SHA256 的官方 KCR 镜像与 `linux/amd64` 平台；范围不匹配、缺少目录、
默认版本被禁用或不兼容时明确拒绝，不回退到旧框架或任意其他镜像。
每次解析重新读取 Server，预发候选 `preview` 不能作为生产目录中的启用版本。

镜像工程提供独立发布脚本，先校验实际 registry manifest/config 摘要和平台，再预览该
Studio 范围的数据库变更；写入要求匹配预览版本，并使用事务锁保护并发发布。
已发布版本内容不可变，只允许启停；升级新增版本、切换默认值，保留历史镜像引用。
2026-10-08 已发布 `pre-online / cn-beijing-6` 的 `0.0.1-a27bc5d` 候选目录，真实 KOP 查询
对 DSH Native、Harness、Codex 均返回摘要
`sha256:ca6925addde8bf2face4fa3e97ba305f770edade3e33eec90309c5e242fbdd40`。
目录携带持久化、完整资源组合、Codex 命令沙箱的未验收说明；目录查询本身不能替代部署验收。

已有 `runtime.catalog` 服务用于 ManagedRuntime 的解析，不直接套用其中的旧 Python
启动规则。这里继续采用通用 Container 合同；若所需元数据不能由现有配置接口承载，
以具体缺口补充合同，而不新增另一套运行服务。
