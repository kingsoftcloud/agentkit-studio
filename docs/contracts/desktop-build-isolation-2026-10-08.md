# 桌面打包与开发网页隔离验收

## 原问题与复现

原 macOS 打包入口在开发网页使用的 DSH checkout 中执行官方 `build:official`。
该步骤会依次清理、重建客户端模块，触发正在运行的 Host 向浏览器推送多次插件热替换。

真实网页已加载原生会话时执行 `pnpm run build:official`，构建后 Agents 按钮数量由 1 变为 0，
页面空白。控制台同时出现 `uiConversation.binding: unknown session` 与
`ctx.remote.dynamicCordisRunner.syncInspectManifest is not a function`。完整刷新后界面恢复，
没有删除会话或清空数据；此现象验证的是全量发布重建与开发热替换冲突。

## 修复边界

所有 Studio `desktop-package-*` 目标改为调用独立 DSH 构建 checkout 中的原官方脚本。
checkout 基于固定 commit 和完整版本化补丁创建；依赖、客户端产物与桌面运行时各自在缓存目录生成。
不拷贝开发 checkout 的其他修改、个人配置、Profile 或 node_modules，也不修改 DSH 私有热替换逻辑。
新增宿主修复须先记录为版本化补丁，才能进入该产物。

相同缓存互斥使用；缓存源码被改动时拒绝继续，不自动清理用户文件。
开始官方流水线前冻结插件 tarball 输入，避免另一次同版本打包覆盖正在使用的包；成功或失败后清理临时输入。
签名配置仅按原官方文件语义临时提供，保留原文件型凭证的相对路径含义，结束后删除临时副本。
本次未执行真实签名或公证，仅验证配置投影及失败清理。

## 验证记录

- 十一项定向测试覆盖真实 Git clone/patch 的构建隔离、独立依赖、错误基线和补丁、修改保护、锁互斥、带空格路径，以及通过真实 Make 入口验证交付成功/失败、缺失/空镜像、缓存旧镜像不误报、临时签名配置失败清理和插件输入快照。全量检查 355 项通过，插件 tarball 208 个文件完整性检查通过。
- 连续两次真实 macOS ARM 构建通过，分别验证首次依赖安装与缓存复用；第二次包含最终插件输入快照实现。官方运行时、原生模块和 DOCX/XLSX/PPTX 转 PDF 冒烟均通过。
- 构建期间原网页无需刷新或重启即可打开 Agents 并读出 29 条记录，资源库及运行资源聚合页均正常读取；两次构建结束后原开发 checkout 的 74 个客户端文件摘要仍一致，开发 Host PID 未变化。截图：`.artifacts/e2e-package-isolation-20261008.png`。
- 最终 DMG 为 501827578 字节，SHA256 `d0132f0ea59098a6d0a884e4510da997d3baf85735bfac55c41d21a0d61eb35b`。镜像校验、只读挂载通过；三份构建脚本、四份相关运行时文件和客户端均与源码逐字节一致。直接执行包内 Node v24.21.0、Codex 0.159.2 成功，Studio A 图标摘要与已验收版本一致。挂载验证后卸载镜像，没有替换用户正在使用的 App。

## 尚未覆盖

本修复隔离发布构建，不声称修复 DSH 开发者主动全量重建时的所有热替换问题。
用户正在运行的独立桌面 App 没有替换或重启。云端资源可携带部署、真实签名和公证仍须各自验收。
