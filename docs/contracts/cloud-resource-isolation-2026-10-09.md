# 云端知识库、渠道与版本切换验收

本轮使用已核验的子账号，在预发通过 KOP 和 Studio 部署编排创建三个独立测试 Agent。
共享镜像为 `0.0.1-94abbbd`，模型为 `glm-5.3-flash`，每个实例申请 20 GiB 持久卷。
没有更换日常开发 Host，也没有关闭 TLS 校验或 Codex 沙箱。

## 独立知识库

三个冻结包都只绑定模型和同一个验收知识库，不含记忆库、MCP、Skill 或其他插件。
使用全新会话询问验收文档中的标记；标记不在用户输入、系统提示词、Agent 定义或资源名称中。
已单独确认知识库检索接口返回两条记录且包含该标记。每次云端响应核对冻结 Agent/Build
身份、标记、仅在系统提示词设置的前缀、增量文本、非零用量和无外部工具调用。

| 运行时 | 文本帧 | 输入 / 输出 tokens | 首文本耗时 | 结果 |
| --- | ---: | ---: | ---: | --- |
| AgentKit Harness | 17 | 918 / 207 | 2.14 秒 | 通过 |
| DSH Native | 15 | 918 / 171 | 2.05 秒 | 通过 |
| Codex | 12 | 9047 / 118 | 3.58 秒 | 通过 |

这补齐了此前全资源包中知识库与记忆库无法区分的问题。它验证的是上述知识库和文本场景，
不等于三种运行时的所有资源组合均已验收，也不证明 Codex 的命令沙箱可用。

## 渠道与冻结版本

Harness 使用同一云端 Agent ID 和同一渠道配置，依次验证：

1. Revision 1 绑定知识库：直接对话与渠道消息都返回正确文档标记。
2. 升级到 Revision 2，移除知识库并更换系统前缀：实际入口确认目标包与切换 ID；
   直接对话和渠道 `/reset` 后的新会话均使用新前缀、说明未绑定知识库，没有返回旧标记。
3. 回滚到原冻结包：实际入口确认原包及本次回滚 ID；直接对话和渠道重置后的新会话
   恢复原前缀与知识库答案。直接对话为 23 个文本帧，用量 918 / 158 tokens。

渠道配置的 `ConnectorWorkspaceId` 为空，执行路径为云端 Channel Worker → Server →
已部署 Agent，未经过桌面 Connector。三个阶段分别重复提交同一事件，均只发送一次模型回复。
重置和回答分别验证，不把重置确认当作模型执行结果。保留渠道绑定不代表旧响应句柄可以跨版本使用。

平台入口使用 MockAdapter 合成消息；控制面、Channel API、Worker、云端模型和知识库为真实服务。
**这不是 WPS、飞书或企业微信真实消息收发验收。** 原始响应与回执保存在私有目录，公开文档不包含
凭证、资源 ID 或用户内容。测试中曾因辅助进程与页面同时读取同一部署目录产生过中断提示；
停止页面轮询后仅核对已提交更新，未重复提交，实际版本探测确认升级成功。该测试不证明多 Host
同时管理同一数据目录受支持。

本轮三个测试 Agent 均已删除且 `GetAgent` 返回 404；五个专属私有运行包经归属和摘要
核对后清理，下载返回 404；测试渠道及其 peer binding 也已删除。未删除共享镜像、知识库
或日志。实际 PVC 回收和独立账单核销尚未核验。

## 定时任务与剩余边界

本轮只读复查预发 KOP，`ListAgentSchedules` 仍返回 `SERVER_ACTION_NOT_REGISTERED` / HTTP 400。
真实 DSH 页面显示任务目录不可读取并禁用新建，没有把接口错误显示为零任务的成功结果。
需发布[云端调度合同](cloud-agent-operations.md)所列七个 Action；未通过直连 Server 冒充产品入口通过。
既有后台单次调度证据仍有效，本轮没有新增定时任务的资源组合验收。

尚未完成：真实平台消息收发、定时结果投递到指定渠道、三种运行时全部资源组合与升级回滚、
跨子账号访问隔离、Codex 云端命令执行，以及正式签名/公证发行。真实平台消息收发需单独
完成平台配置、收发及回执核验，不以合成事件代替。

## 验收工具

`scripts/verify-deployed-bundle.mjs` 现在会在请求云端前拒绝带答案提示的用例：

- 系统提示词盲测前缀不能出现在用户输入中。
- `isolatedKnowledge` 必须给出预期标记，且标记不能出现在输入、冻结定义或资源配置中。
- 原有包身份、工具结果、流式输出和用量检查继续保留。

自动化检查覆盖把前缀或知识答案写进提示词、名称后导致误判的情况，498 项检查通过。
此前三个真实知识库响应也重新通过了新增的静态检查，无需重复模型执行。
