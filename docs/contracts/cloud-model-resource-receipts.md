# 云端模型与资源调用凭据

模型选择和资源调用凭据以 DSH 公开 `Session.append` 的 `ignorable: true` 扩展事件保存；
它们不改写模型历史。缺少标记会导致冷历史读取拒绝整个会话，镜像门禁必须覆盖重启回放。

## 更新原实例

运行中心选择本地 Agent 和成功的 Build 后，默认选择该 Agent 最近部署的非删除实例。
“检查更新”调用已有 `prepareUpdate`，确认后才使用 `UpdateAgent` 更新镜像和冻结包；
保留云端实例 ID、CPU/内存与持久卷。明确选择“创建新的云端实例”才走创建流程。
使用推荐运行镜像时，同一个 Build 也可以升级镜像；冻结包和镜像均未变化则拒绝重复更新。
检查结果包含镜像版本、资源数量、子账号身份和限制，配置变化后需重新检查。

## 每轮模型选择

冻结包保存全部绑定模型及默认模型，凭证只在 Node/容器内解析。
`GET /v1/agentkit/runtime` 返回 `models` 及 `bound-model-selection` 能力；
`POST /v1/responses` 只允许选择这些模型，未指定时使用冻结默认模型。
通过公开 DSH `sessionController.selectModel` 在同一会话串行选择，随后运行原生循环；
Harness/DSH 执行入口按该选择解析唯一的已绑定提供商与模型，实际网关请求和凭证随之切换。
不会更改全局默认模型，也不将桌面 Prompt、工具目录或资源内容发送到云端。
重启重放保留该次请求的模型，同一请求 ID 改模型或输入会被拒绝。
新增模型需要编辑 Agent、构建并更新；旧镜像没有此能力时不悄悄退回默认模型。

## 执行凭据

每轮先核对云端响应中的 Agent、Build、Response ID 与所选模型，再保存执行凭据。
原生会话顶部“云端”按钮显示实例、环境和最近响应；观测页显示 `executionLocation=cloud`。
本机保存的是云端执行结果的记录。DSH 原生会话仍保留本机历史，不能把历史存储位置当作
执行位置。未核验的响应不会保存为云端成功；历史版本没有凭据时不补造记录。

资源调用产生公开 DSH 自定义事件 `studio/resource-check`，通过 Responses 扩展事件
`response.resource_check` 及完成响应的 `metadata.agentkit.resourceChecks` 传回。
仅记录资源 ID、动作、状态、耗时、命中数、定义数量或写入受理标志，排除内容和凭证。
重放读取真实的历史资源事件，失败保留错误码。

- 知识库：容器使用冻结 Dataset ID 调用检索接口，把实际片段交给模型；零命中不等于没有绑定。
- 记忆库：容器召回并在正常完成后提交写入；受理不等于立即可召回，需等待服务抽取完成。
- Skill Center：构建时冻结选中空间的实际文件，容器加载定义；加载成功不代表脚本已经执行，
  仍须核对原生 `skill`、`bash` 等工具的实际结果。空间内容变更后须重新构建更新。
- MCP：使用冻结 Endpoint 与目标环境注入的凭证；实际调用由工具卡片展示，目录可见不能代替调用成功。

## 验收边界

2026-10-09 对用户原有 DSH Native r2 实例直接调用鉴权后的云端 Responses：
知识库返回配置文档原文；Skill 工具加载离线 JSON 检查能力，并由云端命令实际运行脚本；
记忆写入后等待 22 秒，在新会话、没有传入预期事实的提问中召回偏好与编号。
响应的 Agent/Build 标识与该实例的冻结 r2 相符。这些调用验证绑定生效，但旧镜像未提供
新增的资源事件和模型切换能力；新镜像必须另外通过容器与预发验证，不能仅凭本机测试认定上线。
