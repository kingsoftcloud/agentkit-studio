# Native Harness — Reference Capability Map (Python → TS migration)

This document is a **reference inventory** of the existing Python Native Harness
capabilities, assembled from the real source in `ksadk-python` (branch
`feat-ksadk-harness-2`). It is deliberately a *reference list*, not a claim that
the TypeScript port in `packages/agentkit-harness-core` has migrated any
particular item. The implemented TS core contracts are in
`packages/agentkit-harness-core/src/contracts.mts`; the two languages are allowed
to differ in serialized field names, so the mapping is organized by **key
semantics and user-visible behavior**, not by field spelling.

Each capability is classified:

- **formal** — part of the locked contract every host must satisfy; enforced by
  validators or the kernel's own invariants.
- **optional** — opt-in via `RunConfiguration` policy fields / port presence;
  the kernel runs without it and rejects misuse when configured.
- **historical-compat** — exists only to preserve already-sealed configurations
  or legacy adapters; new activations should not depend on it.

Source evidence is given as a relative module path and, where applicable, a
relative test path under `tests/`. All paths are relative to the
`ksadk-python` repo root; no absolute paths, credentials, or private
deployment details appear here.

The deterministic oracle fixtures that back the behavioral claims in this
document live in `tests/fixtures/native-reference.json`, generated by
`.artifacts/oracle/export_native_reference.py` (see the bottom of this file).

## 1. Run lifecycle and the phase state machine

The kernel is a pure-transition state machine over `RunPhase`
(`ksadk/harness/native/state.py:38`):

`created → preparing_context → requesting_model → executing_tools →
{verifying | compacting} → finalizing → {completed | failed | canceled |
interrupted}`, plus `paused` and `awaiting_interaction` as wait states.

- **formal** — `NativeKernel` schedules pure transitions and commits effects
  atomically (`ksadk/harness/native/engine.py:157`). Every side effect has a
  persisted intent before dispatch and one atomic receipt/state/event commit
  after dispatch (`engine.py:1418` `_execute`). A lost running effect stops with
  `effect_outcome_unknown` rather than executing again — see fixture
  `lost_effect_not_rerun`.
- **formal** — `next_transition` is a pure function of `(snapshot, config)`
  that returns a `CommitBatch` or `None` for terminal/paused/awaiting phases
  (`ksadk/harness/native/machine.py:271`). The TS contract mirrors this as
  `machine.mts` producing a `CommitBatch`.
- **formal** — terminal phases are immutable: `completed`, `failed`,
  `canceled`, `interrupted` (`state.py:53`). A terminal commit with unconsumed
  pending commands raises `PendingCommandConflict` in the store
  (`stores/native_memory.py:563`).
- **optional** — `fork` starts a new branch at an immutable terminal Run via a
  `ForkingRunStore` (`engine.py:369`, `fork.py`); `start_notification_turn`
  admits a background-notification turn in the source run's session
  (`engine.py:422`).

Evidence: `tests/harness/native/test_kernel.py`,
`tests/harness/native/test_session_fork.py`,
`tests/harness/native/test_history_observation_inheritance.py`.

## 2. Context, compaction, protocol replay, and media

- **formal** — Host-owned request planning and compaction sealing:
  `ContextPlanner` / `ContextDriver` (`context_runtime.py`,
  `context_driver.py`). The caller owns model I/O; the kernel only plans and
  seals. `prepare` and `begin_summary` are the stable entry points.
- **formal** — Compaction is a sealed projection with validated history:
  `context_compaction_projection.py`, `context_partition.py`,
  `context_summary_planning.py`. Source/projection hashes detect inconsistent
  views; they never authenticate arbitrary rewritten state.
- **formal** — Micro-compact projects old completed tool observations while
  retaining canonical execution facts (batch recency, media/error
  protection, Skill retention): `context_microcompact.py`.
- **formal** — Pruning bounds historical tool-output projections without
  changing the transcript: `context_pruning.py`.
- **optional** — Provider protocol replay: `provider_replay_mode` ∈
  `none | reasoning_content | anthropic_content` on `ModelProfile`
  (`model.py:104`). `anthropic-client-compaction/v1` projection policy binds
  replay input to the original sealed compaction (`context_replay.py`,
  `model_runtime.py:456`). Private replay data is never part of a public event
  payload (mirrors TS `Message.providerReplay`).
- **formal** — Request media is host-projected, never fetched from URLs:
  `request_media.py`, `model_adapters/native_openai.py:189` `_native_messages`.
  `image_input_mode` ∈ `native | text_only` gates image input
  (`ModelProfile.image_input_mode`).
- **optional** — Execution-budget observation at the preparation boundary
  (never a deadline extension): `execution_budget.py`, `RunLimits` reserve
  fields.
- **optional** — Context contributors: host-bound `ContextPort` effects with
  non-authorizing data projection (`context_contributions.py`,
  `context_contributor_contract.py`). Up to 16 sources
  (`RunConfiguration.context_sources`).
- **optional** — Finalization wall delivery reserve:
  `RunLimits.finalization_reserve_wall_seconds` and the compaction-reserve
  observation path.

## 3. Tool approval, parallelism, and budget

- **formal** — Tool definition is host-pinned and never projected wholesale to
  the model: `ToolDefinition` (`ports.py:81`). Only `function_schema()`
  (name/description/parameters) is model-visible; `read_only`,
  `concurrent_safe`, `context_role`, `observation_role`, `progress_observation`,
  `context_retention`, `child_budget_policy`, `child_approval_policy`,
  `background_command_policy`, `delegated_read_only`, `delivery_write` are
  host-only. Validators enforce invariants, e.g. `concurrent_safe` requires
  `read_only` and `observation_role == "none"`; `background_command_policy`
  forbids `read_only`/`concurrent_safe` (`ports.py:159`).
- **formal** — Parallel readonly batching: only a contiguous prefix of
  host-declared `concurrent_safe` read-only calls may share one durable effect
  batch; writes, browser actions, and approval-capable tools stay serial
  (`machine.py:303` `next_transition` EXECUTING_TOOLS,
  `machine.py:886` `reduce_parallel_readonly_tools`). See fixture
  `parallel_readonly_batch` (one effect, two calls) vs
  `serial_write_workspace_paths`.
- **formal** — Approval/interaction: a tool returns
  `ToolResult(status="approval_required", interaction_id=...)` → run enters
  `awaiting_interaction`; a `submit_interaction` command with matching
  `interaction_id` and `decision ∈ {allow, deny}` re-dispatches the tool with
  `request.interaction` granted (`machine.py:117` `reduce_command`,
  `machine.py:746` `reduce_tool`). Mismatched ids are rejected at consume
  time. See fixture `approval_match_allow`.
- **formal** — Tool budget: `RunLimits.max_tool_calls`, `max_model_calls`,
  `finalization_reserve_model_calls`, `max_parallel_tools`. `tools_exhausted`
  and `finalization_only` gates refuse tool batches that exceed the remaining
  budget (`machine.py:530`), and `call_room` refuses a new model call when the
  budget is spent (`machine.py:286`). See fixtures
  `model_budget_exhausted_not_success` (failed, not completed).
- **formal** — Tool error recovery: action-local diagnosis grants one trial
  and never re-dispatches the same failing action without new host evidence
  (`tool_error_recovery.py`); a compaction-proof streak counter stops after
  `REPEATED_ERROR_STOP_THRESHOLD = 6` (`tool_error_streak.py`).
- **formal** — Tool interruption: a truncated tool batch is bound to the
  original transcript; interrupted calls get `not_dispatched`/`unknown`
  dispositions, never an invented execution result (`tool_interruption.py`,
  `machine.py:137` `reduce_tool` uncertain → `effect_outcome_unknown`).
- **optional** — Tool hooks: `PreToolUse`/`PostToolUse` durable admission;
  callbacks never own tools or approval (`tool_hook_runtime.py`).
- **optional** — `tool_recovery_policy` ∈ `sealed_local_child/v1`,
  `prepared_local_child/v1`, `resume_prepared_local_child/v1`,
  `resume_local_child_checkpoint/v1` reconciles a lost tool effect via
  `ToolReconciliationPort`/`ToolPreparedRecoveryPort`/`ToolPreparedContinuationPort`/`ToolCheckpointContinuationPort`
  (`ports.py:750`, `engine.py:1428`).

Evidence: `tests/harness/native/test_adapters.py`,
`tests/harness/native/test_canonical_tool_observation.py`,
`tests/harness/native/test_child_approval_bridge.py`,
`tests/harness/native/test_tool_error_recovery.py`,
`tests/harness/native/test_interrupted_tool_history.py`.

## 4. Verification and delivery

- **formal** — Host-owned deterministic verification with durable scoped
  evidence; assertions and verifier code must live outside the agent's
  writable workspace (`verification.py`). The kernel derives paths from
  executed receipts, never from model text.
- **formal** — Verification verdict is a pure transition
  (`verification_runtime.py:64` `reduce_verification`,
  `terminal_verification.py:9` `prepare_terminal_verification`). Outcome
  `verified` requires every required acceptance item to be `passed` **with
  non-empty `evidence_refs`** and `verification_method != "model_assisted"`
  (`completion.py:230`). A missing/absent verifier yields `unverified`, never
  `verified` — see fixtures `no_verifier_unverified` and
  `verifier_no_evidence_unverified` (`qualified_evidence_missing`).
- **formal** — Final-output normalization: `final_output_format` ∈
  `text | json_object | json_value` (`final_output.py`,
  `ports.py:305`). `final_submission_schema` + `final_submission_payload_key`
  admit a `submit_final_output` tool that seals a candidate directly without a
  tool dispatch (`final_submission.py`, `machine.py:491`). See fixture
  `final_submission_schema_tool`.
- **formal** — Delivery artifacts and review: `delivery_artifacts.py`,
  `delivery_review.py` (bounded candidate review/repair, inspired by ZCode's
  Stop continuation boundary), `delivery_review_policy` on `RunConfiguration`.
  Review text has no permission, execution, or acceptance authority.
- **optional** — Workspace delivery write retention in a deadline window:
  `ToolDefinition.delivery_write`, `delivery_artifact_role`.
- **optional** — Output recovery policy `task-or-delivery/v1` distinguishes
  resuming work from completing a text suffix.

## 5. Subtasks, messages, promotion, background, and recovery

- **optional** — Child lifecycle policy `owned-background/v1`/`v2` with a
  `ChildLifecyclePort` (`child_lifecycle.py`,
  `child_lifecycle_contract.py`). The Store remains the ledger; collection is a
  parent effect, not a second registry.
- **optional** — Child promotion `owned-child-promotion/v1`: changes delivery
  only; never launches a Run, replays a tool, changes authorization, or settles
  the child's usage (`child_promotion.py`).
- **optional** — Child input `owned-child-guide/v1` and child release
  `owned-run-release/v1` (`child_input.py`, `engine.py:1064`).
- **optional** — Child approval `owned-child-approval/v1`: routes through the
  original parent/child commands; arbitrary processes need isolation
  (`child_approval.py`, `subagent_adapters/native_child_approval.py`).
- **optional** — Child notifications `ready-before-model/v1` and background
  notifications `completed-before-model/v1` (`child_notifications.py`,
  `background_commands.py`). Notifications admit an observation at a
  controlled model boundary; no notification launches a process or revives a
  stopped Run.
- **formal** — Child budget is parent-owned accounting; child executors never
  write this ledger (`child_budget.py`). Reservations stay charged until a
  terminal receipt settles them, including across compaction and
  serialization.
- **optional** — Background commands `owned-command-launch/v1` with a
  `BackgroundCommandPort` (`background_commands.py`,
  `background_command_contract.py`); observations only through a scoped,
  committed launcher receipt.
- **optional** — Task-chain budget: a finite `task_chain_id` budget accrues
  across a user goal and its notification turns; a high-water-mark ledger
  charges each run once (`stores/native_memory.py:301` `_settle_run_in_lock`,
  `engine.py:561` `task_chain_budget_status`).
- **formal** — Process recovery: reattach rebinds activation resources and
  browser sessions; a running intent with no receipt becomes `uncertain` and
  the run interrupts rather than re-executing (`engine.py:760`
  `recover_activation_resources`, `engine.py:781` `recover_browser_resources`,
  `engine.py:1418` `_execute`). See fixture `lost_effect_not_rerun`.
- **optional** — Model takeover recovery `pure-inference-takeover/v1`
  (`model_takeover.py`, `native/model_recovery.py`): a narrow host grant for
  the ordinary Studio Chat Completions path.

## 6. Hooks and context contribution

- **optional** — Hook port with `PreToolUse`/`PostToolUse`/`PreCompact`/`Stop`

## 7. Commands, lease, and store contract

- **formal** — `RunCommand` kinds and priority (`state.py:393`):
  `cancel(100) > policy_revoked(95) > submit_interaction(90) > cancel_child(85)
  > pause(80) = resume(80) > promote_child(70) = message_child(70) > steer(60) =
  guide(60)`. `advance` consumes the highest-priority pending command first.
  See fixture `command_priority_ordering` and `cancel_priority_over_inflight_tool`.
- **formal** — `RunStore` contract (`stores/native_contract.py`): atomic
  `create`/`create_turn`/`create_fork`/`create_notification_turn`, fence-gated
  `claim_intent`, CAS `commit` (idempotent by `commit_id`+payload), command
  dedup by `command_id`. `MemoryRunStore` is the in-process reference
  (`stores/native_memory.py`); `SQLiteRunStore` is the durable implementation.
  See fixtures `store_command_dedup`, `store_commit_idempotent`.
- **formal** — Lease/fence: `RunLeaseController` owns local worker ownership
  separately from loop decisions (`lease.py`). `acquire` bumps the fence; every
  commit checks the fence.
- **formal** — `pause`/`resume`: pause records `paused_from`; resume returns
  to `paused_from` or `preparing_context` (`machine.py:110` `reduce_command`).
  See fixture `pause_resume`.

## 8. Model port and adapters

- **formal** — `ModelPort.complete(request) -> ModelTurnResult` and
  `StreamingModelPort.stream` (`ports.py:728`). The TS contract spells this
  `ModelPort.generate(request, emit)` — an allowed naming/shape difference.
- **formal** — `normalize_response` classifies one sealed attempt into
  `ModelResponseKind` without merging snapshots or inferring success
  (`model.py:477`). See fixture `normalize_response_classification`.
- **formal** — Provider retry budget is separate from the malformed/empty
  budget: `max_provider_retries` (transport failures) vs `max_retries`
  (malformed/empty). `retry_delay` is a pure backoff with bounded upward
  jitter; an explicit server `Retry-After` is preserved exactly
  (`model_runtime.py:240`). See fixtures `provider_retry_budget_exhausted`,
  `malformed_tool_call_retry_exhausted`, `retry_delay_pure`.
- **formal** — Output continuity: `output_limit` continues with a
  `continuation_fragment`/`continuation_observation` and explicitly states
  "Incomplete tool calls were not executed"; `max_continuations` and
  `max_output_restarts` bound it (`machine.py:635`,
  `completion_text.py`). See fixture `output_limit_tools_not_executed`.
- **historical-compat** — `from_reasoning_turn` bridges a legacy
  `HarnessReasoningTurn` while preserving its missing finish reason as `None`
  (`model.py:545`); new adapters should use `normalize_response` with real
  protocol completion metadata.
- **optional** — `OpenAICompatibleModelPort` performs exactly one HTTP request
  per attempt with optional SSE and sealed finish reasons
  (`model_adapters/native_openai.py:486`). MCP media/result projection
  (`model_adapters/native_mcp_media.py`, `native_mcp_result.py`) preserves
  structured data and explicit media without granting URLs/payloads host
  authority.

## 10. Studio product integration (native_product / native_*)

The `ksadk/studio/native_*.py` layer wires the host-independent kernel into the
Studio product. These are **host-side adapters**, not kernel contract; they
project Studio Build/Gateway facts into the Native ports.

- `native_product.py::StudioNativeProductComposer` — composes the kernel with
  Studio tools, workspace, verifier, subagents, browser, hooks, context, and
  background command ports for one activation.
- `native_model_port.py` — Studio ModelGateway → Native `ModelPort` (sealed
  finish reasons, tool batches, usage; never interprets reasoning text as a
  final answer or executable tool call).
- `native_tool_port.py` — Build-locked Studio tools → Native `ToolPort`
  (Build owns the allowlist/source hashes; Studio owns authorization; Native
  validates frozen schema/scope per call).
- `native_workspace_port.py`, `native_directory_observation.py`,
  `native_workspace_diagnostics.py` — read-only workspace observer bound to
  one activation scope.
- `native_verification_presentation.py`, `native_acceptance.py`,
  `native_final_shape.py` — present the terminal verifier separately from the
  model candidate; a shape verifier can reject but never proves the semantic
  goal (`outcome` stays `unverified`).
- `native_subagent_port.py`, `native_child_*.py` — bind Build sub-agents to
  isolated Native child runs; read roles share observations, write roles use
  an independent directory and controlled merge.
- `native_browser_port.py` — run-scoped browser continuity for a locked
  Studio Native browser tool.
- `native_hook_port.py`, `native_hook_registration.py` — consume locked Harness
  Hook sources under current Studio Run authority.
- `native_context_port.py`, `native_context_evidence.py`,
  `native_context_registration.py` — locked DSH Context sources consumed as
  scoped, bounded data.
- `native_background_command_port.py`, `native_background_locator.py`,
  `native_background_ownership.py`, `native_background_wakeup.py` — observe
  background command status only through a scoped, committed launcher
  receipt.
- `native_memory_*.py` — DSH Memory recall/turn/sources/tool_port/acceptance/
  context/flush projection into the Native effect and approval boundary; an
  assistant promise is not a persisted fact.
- `native_model_recovery.py` — explicit host grant for the narrow ordinary
  Studio Chat Completions path (route/type checks prove local construction
  identity).
- `native_recovery.py`, `native_terminal_recovery.py` — reattach an opt-in
  SQLite Native Harness run after a local Studio restart; repair a derived
  trace from already-published terminal facts without changing the Run.
- `native_session_engine.py`, `native_scope.py`, `native_kernel_admission.py`,
  `native_command_policy.py`, `native_planning.py`, `native_options.py`,
  `native_user_input.py`, `native_documents.py`, `native_output_fields.py`,
  `native_project_instructions.py`, `native_skill_source.py`,
  `native_mcp_disclosure.py`, `native_inventory_disclosure.py`,
  `native_language_diagnostics.py` — supporting Studio projections.

## Coverage notes and contract questions

The fixture set covers the priority list from the task with **20 real
scenarios** (≥12 valid), all captured from live `NativeKernel` /
`MemoryRunStore` / pure-transform runs and frozen deterministically.

**Covered:** closed-loop verified turn; single-tool verified turn; parallel
readonly batch vs serial write; cancel priority over an in-flight tool;
pause/resume; approval match (and mismatch rejection); lost effect not
re-run; model-budget exhaustion is not success; malformed-tool-call retry
budget; provider-retryable-error retry budget (separate); output-limit tools
not executed; no-verifier → unverified; verifier-no-evidence → unverified;
final-submission-schema tool; store command dedup; store commit idempotency;
`normalize_response` classification; `retry_delay` pure backoff; command
priority ordering.

**Not yet covered by fixtures (capability present, no deterministic oracle
scenario here):** compaction/micro-compact sealing under real context
pressure; context-source contributor effects; child lifecycle/promotion/
notification turns; background command observation turns; task-chain budget
cumulative settlement; browser reobservation before candidate acceptance;
artifact page-budget/partial-read capacities; tool hook admission decisions;
precompact/stop hook continuations; activation-resource and browser-resource
rebind on reattach; SQLite durable restart. These are documented above with
source/test evidence and are good candidates for a follow-up fixture batch
that wires the corresponding optional ports.

**Contract questions for the TS core owner (not blocking, flagged for
review):**

1. The TS `RunStore` contract lists `acquire/renew/release` lease methods and
   `acknowledge(projection)`. The Python `MemoryRunStore` exposes `acquire`
   (returns a fence token) but lease renew/release live in `RunLeaseController`
   (`lease.py`), and projection acknowledgement is on the SQLite store. Should
   the TS `RunStore` keep lease on the store or split it like Python?
2. The TS `ToolDefinition` carries `permissions: string[]` and `timeoutMs`,
   which have no direct Python field (Python uses `execution_policy_digest`
   and `RunLimits.effect_timeout_seconds`). Confirm the TS side maps these to
   host-owned execution policy, not model-visible fields.
3. The TS `ModelPort.generate(request, emit)` takes a streaming `emit`
   callback; Python splits `complete` (one shot) and `stream` (async
   iterator). Confirm whether the TS port is always streaming or whether a
   non-streaming fast path is allowed.
4. Python `ModelResult`/`ModelTurnResult` has `text_commit_version
   "provider-finished-text/v1"` attesting a bounded text-only output-limit;
   the TS `ModelResult` has no equivalent field. Is the bounded-text
   distinction folded into `kind: "output_limit"` plus `text` on the TS side?
5. Python `RunSnapshot.outcome` includes `partial` and `blocked` (in addition
   to `verified`/`unverified`/`failed`); the TS `Outcome` is
   `verified | unverified | blocked | failed` (no `partial`). Confirm whether
   `partial` is folded into `unverified` on the TS side or dropped.

## Current TS verification coverage

The reference inventory above remains the migration scope. The TS Host now
composes the terminal delivery verifier (`native-verification.mjs`) with
scoped durable artifacts, exact-file observations, strict output-shape helpers
and authorized cold browser observations. Shape and smoke success retain
`not_run`; only independently observed exact-file bytes can pass that specific
item. Candidate/context/contract/workspace binding, bounded repair and a real
process exit before the verifier receipt commit are covered by targeted tests.
The Studio factory also pins each new goal to its original parent Run, while
core steering uses goal-revision CAS and persists replacement contracts.

This does not close checkpoint verification between tool batches, optional
vision feedback, all product consumers or clean installation without Python.
The Python-list parser pins Unicode 14.0.0 and the CPython 3.11 default decimal
integer limit of 4300 digits; an unhashable literal becomes a bounded rejection
instead of the source's uncaught TypeError. Structured model JSON still needs
lossless handling of integers beyond JavaScript's safe range. These differences
and open requirements prevent a claim of completed lossless migration.

## Oracle reproducibility

The fixture file `tests/fixtures/native-reference.json` is generated by:

```
PYTHONDONTWRITEBYTECODE=1 <reference-repo>/.venv/bin/python \
    .artifacts/oracle/export_native_reference.py
```

The export script drives the real `NativeKernel` /
`MemoryRunStore` / pure transforms with scripted ports, normalizes each output
to deterministic semantic fields (stripping volatile identity, timestamps, and
digests), and writes the JSON. No `expected` value is hand-written; the
normalized outputs are captured from real runs and then frozen. Re-running the
script reproduces the fixture byte-for-byte (verified deterministic across
runs). The Node test `tests/native-reference-fixtures.test.mjs` validates the
fixture's structure, normalization protocol, and per-scenario invariants
without depending on Python.
