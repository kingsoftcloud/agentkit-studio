# 插件展示与 Host 兼容性

当前基线为 DSH `0.2.1-rc.2`。以下展示接口按该版本的插槽声明和首页组件核对；不维护更早 DSH 版本的适配分支。

| 展示能力 | 维护方式 |
| --- | --- |
| 侧栏名称与图标 | 官方 `sidebar.brand.name`、`sidebar.brand.mark` 插槽 |
| 首页图标 | 官方 `conversation.hero.brand.mark` 插槽 |
| 首页标题与提示 | locale 词条；有 `locale.override()` 时按插件 scope 贡献，缺少时保留宿主原生词条 |
| 浏览器标题与 favicon | Studio 的文档效果和 Web 注入，由插件生命周期释放 |
| 桌面应用身份、签名、公证、更新 | 桌面包装及发行流程，不能由 Web 插槽代替 |

该基线没有声明 `conversation.hero.brand.name`。首页标题来自 `hero.headline`，因此不向不存在的插槽注册组件，也不通过 DOM 改写接管宿主词条。支持文案贡献的宿主仍在卸载时释放所属覆盖；部分安装失败也释放此前注册的贡献。

文案扩展是展示层的可选能力。Agent 预设组合、自动化、冻结运行时及请求指纹仍由既有 Host 兼容性检查决定；缺少执行契约时继续拒绝运行。页面能挂载、原生会话列表能打开，都不能替代 Agent 真实执行验收。

源码测试验证缺少可选文案扩展时原生词典不变，以及覆盖贡献的释放和失败回退。公开门禁和 patched DSH Host 检查验证维护基线；它们不代表未经修改的官方 npm 运行时、完整 Web 交互或原生安装更新已完成验收。需要验证这些场景时，应使用精确版本、隔离 Profile 和独立数据目录，分别记录加载、卸载、历史保留和执行结果。
