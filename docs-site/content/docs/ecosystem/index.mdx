AgentKit Studio 不是封闭应用。它自身就是一个 DSH 插件，同时把 DSH 的插件生态、模板生态和 Host 兼容契约暴露给你。

## 四个扩展面

| 扩展面 | 你要解决的问题 | 去哪里 |
| --- | --- | --- |
| DSH 插件 | 写一个能在 DSH 宿主里加载的插件包 | [DSH 插件作者指南](./dsh-plugin-authoring.mdx) |
| 插件市场 | 让插件出现在市场里，或自建远程索引 | [插件市场](./plugin-market.mdx) |
| 专家模板 | 用 JSON 定义专家与专家团 | [专家模板](./expert-templates.mdx) |
| Host 兼容 | 判断当前 Host 能否执行 Studio 能力 | [Host 兼容性](./host-compatibility.mdx) |

## 产品里的入口

| 界面 | 槽位与 id | 顺序 | 源码 |
| --- | --- | --- | --- |
| 插件市场 | `plugins.item` / `agentkit-dsh-plugin-market` | 50 | `src/client/dsh/mount.mjs:49` |
| Codex 插件 | `plugins.item` / `agentkit-codex-plugin-market` | 90 | `src/client/dsh/mount.mjs:52` |
| 专家目录 | 智能体面板内页 | — | `src/client/pages/expert-catalog.mjs` |
| 模板广场 | 智能体面板内页 | — | `src/client/pages/template-square.mjs` |

Studio **不提供插件市场**：市场就是 DSH 官方「插件」页的「已安装 / 发现」两个 tab，索引由 Host 的 `pluginMarket` 服务读取。Studio 只做两件事——把随包内置的社区索引添加到默认源，以及默认启用「自定义插件索引」与 Computer Use 两个官方 bundle。

<Callout type="info" title="市场只做元数据">
  安装、启用/停用、更新、卸载全部由官方 DSH 插件管理器执行；索引的抓取、校验、缓存、搜索与分页由官方 `pluginMarket` 服务完成。
  Studio 不写 profile、不做兼容性判定、不加载运行时。
  源码：`src/plugin-market.mjs:1-16`、`src/host/default-bundles.mjs:1-18`。
</Callout>

## 三个信任边界

生态扩展最容易踩线的地方，是分不清「谁有权决定什么」。

| 边界 | 谁能决定 | 不能做的事 |
| --- | --- | --- |
| 目录内容 | 索引文档可以描述「提供哪些插件、怎么展示」 | ❌ 不能声明 `expectedEntries` / `service` / `readinessNote`——这些探针留在精选清单里，否则第三方文档可以诱导适配器调用任意的 Host 服务 |
| 插件安装 | 官方 DSH 插件管理器 | ❌ 市场不能自己写 profile、不能自己执行安装 |
| 能力探针 | Host 自己 | ❌ 远程文档不能声明「我确实加载成功了」 |

源码：`src/plugin-market.mjs:22-40`、`src/host/default-bundles.mjs:9-16`。

## 版本与身份

一个 Studio 插件对外只想暴露一个身份，但实际有四个版本号同时存在：

| 版本 | 值 | 来源 |
| --- | --- | --- |
| 插件版本 | `0.0.16` | `package.json#version` |
| DSH 基线 | `0.2.2-rc.1` | `studio.plugin.json#requiredDsh` |
| Host API | `dsh-native/0.2.2-rc.1` | `studio.plugin.json#requiredHostApi` |
| Host 契约号 | `1` | `studio.plugin.json#requiredHostContract` |

桌面应用还有第五个版本（`<dsh version>.<YYYYMMDD>.<ordinal>`），它**不是**插件 semver。完整的四维对照表在
[版本兼容表](../releases/compatibility.mdx)。

## 术语速查

本章反复出现的几个词，先统一口径：

| 术语 | 代码 / 值 | 一句话 |
| --- | --- | --- |
| 插件市场 | `plugins.item` 槽位 | DSH 官方插件页里的一行，负责**发现** |
| 内置社区索引 | `assets/plugin-market/index.json` | 随产品出厂的 `format: 1` 索引，由 Host 提供 |
| 索引源 | `pluginMarket` 的 `indexes` | 属于当前 profile 的索引 URL，可在「发现」页增删 |
| 能力探针 | `expectedEntries` / `service` | 只有内置条目能声明，用来验证「Host 真的加载了」 |
| 专家团模板 | `agentkit.studio.team-template/v1` | `kind: "team"` 的多角色定义 |
| 兼容契约 | `requiredHostContract: 1` | 能力面变更时递增的整数 |

## 常见误解

| 误解 | 事实 |
| --- | --- |
| 「装好插件就有市场里的全部能力」 | 市场列出的是**可安装**的包；是否可用取决于 Host 是否加载成功，见[就绪校验](./plugin-market.mdx#就绪校验) |
| 「索引能声明一切」 | 索引只声明展示与安装信息；Host 能力探针留在精选清单里，见[安全与信任](./plugin-market.mdx#安全与信任) |
| 「Codex 插件和 DSH 插件是同一套」 | DSH 插件走官方插件页；Codex 是独立的 `plugins/codex-*` 链路，安装目标也不同 |
| 「专家团就是几个 Agent 的列表」 | 专家团是 `kind: "team"` 的独立模板，角色只能引用不可变模板，不能引用普通 Agent |
