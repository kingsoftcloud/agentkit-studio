部署到云端（cloud deployment）把一个**构建成功的冻结版本**变成 7×24 常驻的托管运行时实例。
实例有独立 ID、规格和持久化存储，删除重建后会话历史仍保留。

<Callout type="info" title="前置条件">
  - 至少一个 **本地创建**的 Agent，且已有 `SUCCEEDED` 的构建版本。
  - 已配置**子账号** AK/SK。主账号不能创建云端资源。
  - 已连接 AgentEngine Server；未连接时部署区会提示「云端发布不可用」，此时只能导出运行包。
</Callout>

## 操作步骤

<Steps>

<Step>
### 打开构建与部署

**运行中心 → 构建与部署**。页面顶部是三步编号：

| 步骤 | 编号 | 说明 |
| --- | --- | --- |
| 构建 | 1 | 冻结当前提示词、模型和资源绑定 |
| 部署 | 2 | 创建或更新云端实例 |
| 云端实例 | 3 | 部署记录与操作 |

没构建成功时第 2 步是暗色的，提示「构建成功后可以部署」。
</Step>

<Step>
### 选中 Agent 与构建版本

1. 右上角「目标 Agent」选择器里挑一个。
2. 在「冻结版本」下拉里选一个 `SUCCEEDED` 的版本——失败的版本不可选。

<Callout type="warn" title="只有最新构建的版本能直接部署">
  当前配置的 revision 与最新成功构建不一致时，第 1 步会提示「配置已更新到 `r<n>`」。
  先重新构建，否则部署出去的仍是旧配置。
</Callout>
</Step>

<Step>
### 选择部署目标

「部署到」下拉有两个选项：

| 选项 | 行为 |
| --- | --- |
| 更新「`<实例名>`」的当前实例 | 复用现有实例 ID、规格和存储，只切换冻结版本 |
| 创建新的云端实例 | 按下面选的规格新建，产生新的实例 ID 和新的账单 |

更新已有实例时，「运行镜像」是一个开关：「使用当前推荐的运行镜像」。关掉它才能指定别的镜像版本。
</Step>

<Step>
### 选择实例规格

创建新实例时选规格，比例必须是 **1:2、1:4 或 1:8**：

| 分组（比例） | 可选核数 | 举例 |
| --- | --- | --- |
| 通用 · CPU / 内存 1:2 | 1 / 2 / 4 / 8 / 16 核 | 默认 2 核 → 4 GB |
| 更多内存 · 1:4 | 1 / 2 / 4 / 8 / 16 核 | 2 核 → 8 GB |
| 更多内存 · 1:8 | 1 / 2 / 4 / 8 / 16 核 | 2 核 → 16 GB |

更新已有实例时规格是只读的，显示当前值。
</Step>

<Step>
### 确认对话存储

存储固定 **20 GiB 持久化云盘**，挂载在运行容器的 `/home/node`。Agent 状态、会话历史和**工作区**都在这个目录下，实例重建后仍然保留。

<Callout type="warn" title="按天计费，删除前先备份">
  云盘按天计费。删除实例前请先备份需要留下的历史——删除后这份目录不会回来。
  不再提供「临时存储」选项：那个选择只会改变每天的账单，还会在实例重建时静默丢掉会话历史。
</Callout>
</Step>

<Step>
### 跑部署检查

点 **检查部署**（更新实例时是 **检查更新**）。检查是只读的，不会创建任何云端资源，返回一屏「部署检查结果」：

| 行 | 内容 |
| --- | --- |
| 部署位置 | 环境（`pre-online` 显示为「预发环境」）· 区域 |
| 实例规格 | CPU 核数 / 内存 GB · 1 个实例 |
| 对话存储 | `20 GiB · /home/node` |
| 运行时 | 运行时类型 · 当前镜像版本 |
| 目标运行镜像 | 镜像版本 · digest —— 升级前要核对的部署身份 |
| 已绑定资源 | N 个模型 · N 个 MCP · N 个 Skill · N 个云端资源 |
| 操作人 | 子账号用户名或「主账号」 |

检查同时验证三件事：**冻结版本**、**资源凭证**、**部署位置与配额**。任何一项不通过，检查就失败，不会走到确认按钮。

下面的警告不要跳过，它们是计费和不可逆操作提示，例如「单副本按所选规格创建；费用以平台实际计费为准」。
</Step>

<Step>
### 确认创建

点 **确认创建云端实例**。提交后提示「部署已提交，进度会自动更新」，记录出现在第 3 步。

<Callout type="error" title="提交结果未确认时不要新建">
  如果提示「提交结果未确认，请保留当前页面并核对部署记录」，**不要**刷新后重试创建。
  到第 3 步对那条记录点 **核对创建结果**，用同一个请求标识对账；重复提交会真的多出一个实例。
</Callout>
</Step>

</Steps>

## 部署状态：你该关心的 10 个

列表每 **5 秒**自动刷新一次；页面切到后台时暂停轮询。状态值共 19 个，日常只需要认这 10 个：

| 状态 | 界面文案 | 含义 | 你要做什么 |
| --- | --- | --- | --- |
| `PREPARED` | 待提交 | 部署记录已生成，还没提交 | 不需要操作 |
| `UPLOADING` | 上传运行包 | 正在上传冻结运行包 | 等待 |
| `CREATING` | 创建中 | 平台正在创建云端 Agent | 等待 |
| `PROVISIONING` | 准备实例 | 实例已创建，正在准备 | 等待 |
| `CONFIGURING` | 配置访问令牌 | 正在写入访问令牌 | 等待 |
| `TOKEN_PENDING` | 等待配置生效 | 令牌已写入，等生效 | 超过一两分钟仍是这个状态，用 **修复访问配置** |
| `STARTING` | 启动中 | 入口已就绪，等版本探测通过 | 等待 |
| `READY` | 就绪 | 实例可用 | 点 **开始对话** |
| `ACTION_REQUIRED` | 需要处理 | 需要人工介入，实例可能仍在运行 | 看「详情」里的失败码再决定 |
| `FAILED` | 失败 | 创建失败 | 看「详情」里的 `code` 与 `message` |

其余状态按需查：`UPLOADED`（已上传，等创建）、`AVAILABLE_UPDATING`（入口可用但平台在更新，可以对话，别在这时升级）、`DELETING`（删除中）、`DELETED`（已删除，需打开「显示已删除」才看得到）。

## `*_UNKNOWN` 状态怎么处理

带 `_UNKNOWN` 后缀的四个状态表示**平台没有确认上一次写操作的结果**。它们不会自己往前走，必须人工对账：

| 状态 | 界面文案 | 处理动作 |
| --- | --- | --- |
| `UPLOAD_UNKNOWN` | 上传结果待核对 | 点 **核对创建结果**；确认包已上传后由平台继续创建 |
| `CREATE_UNKNOWN` | 创建结果待核对 | 点 **核对创建结果**。**绝对不要**重新创建——对账会认领已经创建出来的实例 |
| `UPDATE_UNKNOWN` | 更新结果待核对 | 点 **刷新状态** 触发版本探测；探测通过会自动落到 `READY` |
| `DELETE_UNKNOWN` | 删除结果待核对 | 点 **刷新状态**；云端已不存在时会自动落为 `DELETED` |

这四个状态和 `ACTION_REQUIRED`、`FAILED`、`TOKEN_PENDING` 一起算「需要处理」。别的 Agent 有待处理记录时，列表顶部会提示「其他 Agent 有 N 条部署需要处理」，点 **查看全部** 切到全部范围。

## 成功后的样子

- 记录行状态是 `READY`，色调为绿色。
- 行内出现 **开始对话**（`READY` 和 `AVAILABLE_UPDATING` 才有）。
- 展开「详情」能看到：云端 Agent、运行时、运行镜像（含 digest）、构建版本、对话存储。
- 点 **日志** 能拿到运行日志；没有日志时显示「暂无日志」。

## 常见错误

| 错误码 | 原因 | 处理 |
| --- | --- | --- |
| `CLOUD_SUBACCOUNT_REQUIRED` | 当前身份不是已核验的子账号，或子账号与部署记录不符 | 到设置里更新云端凭证；不会改用主账号创建资源 |
| `DEPLOYMENT_AGENT_UNSUPPORTED` | 目标不是本地创建的 Agent Build | 只部署本地创建的 Agent |
| `DEPLOYMENT_RESOURCE_INVALID` | CPU / 内存比例不是 1:2、1:4 或 1:8 | 从规格下拉里选 |
| `DEPLOYMENT_TYPE_INVALID` | 部署类型无效 | 用界面发起部署，不要手拼请求 |
| `KS3_BUCKET_REQUIRED` | 无法确定账号默认存储桶 | 核验云端身份，或在高级设置里指定 KS3 Bucket |
| `MCP_CREDENTIAL_MISSING` | 绑定的 MCP 缺有效凭证 | 补齐 MCP 凭证后重新检查 |
| `DEPLOYMENT_ENV_CONFLICT` | 多个 MCP 生成了冲突的凭证环境变量 | 去掉重复的 MCP 绑定 |
| `MANAGED_RUNTIME_MODEL_INVALID` | 运行包缺少默认模型 | 回到 Agent 里指定模型并重新构建 |
| `DEPLOYMENT_ACCOUNT_CHANGED` | 云端凭证或环境与部署记录不同 | 切回原配置后再管理该记录 |
| `DEPLOYMENT_CREATE_UNCONFIRMED` | 创建结果尚未确认 | 先 **核对创建结果**，不要重新创建 |
| `DEPLOYMENT_PROVENANCE_MISMATCH` | 云端 Agent 与冻结部署记录不一致 | 停止管理操作，核对云端实例来源 |
| `DEPLOYMENT_RECORD_CORRUPT` | 本机部署记录损坏 | 保留文件并核对云端结果，不能重新提交创建 |
