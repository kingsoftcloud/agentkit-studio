自动化（automation）解决的是「**到点自己跑一次**」：一条提示词 + 一条触发规则 + 一个目标 Agent。
它不改变 Agent 的能力，只决定什么时候把哪句话发给它。

<Callout type="info" title="前置条件">
  - 至少有一个 Agent。本地自动化需要应用保持运行；云端自动化需要该 Agent 已部署到云端。
  - 云端投递到渠道会话，还需要在 [Channels](./channels.mdx) 里绑定过这个云端 Agent，并与机器人完成过一次对话。
</Callout>

## 两种调度目标

| 执行位置 | 在哪里跑 | 关闭应用后 | 适用 |
| --- | --- | --- | --- |
| 本地 | 你这台设备的 Host 进程 | 不会执行 | 需要在你的工作区里改文件、跑命令 |
| 云端部署 | 云端常驻实例 | 仍然按计划执行 | 定时摘要、巡检、巡检类通知 |

页面顶部有一个状态徽章：**调度运行中** 表示触发循环已经起来，**调度待就绪** 表示还没起来（例如 Host 刚启动或没有可用的执行器）。
本地与云端共用同一套触发规则语法，区别只在执行位置和投递能力。

## 操作步骤

<Steps>

<Step>
### 打开自动化

**运行中心 → 自动化**。先在上方切 **本地** 或 **云端部署**——切换会清空当前筛选和正在编辑的表单。

<Callout type="warn" title="两种位置分开存储">
  本地任务和云端任务各存一份，互不可见。切换位置后看到的列表是独立的，不要以为任务丢了。
</Callout>
</Step>

<Step>
### 新建一条自动化

点右上角 **新建自动化**，或者从「从常用任务开始」里挑一个模板预填：

| 模板 | 触发规则 | 提示词示例 |
| --- | --- | --- |
| 每日简报 · 工作日 10:00 | `0 10 * * 1-5` | 整理今天工作区中的变更并给出摘要 |
| 定期巡检 · 每 30 分钟 | 固定间隔 `1800` 秒 | 检查服务状态，发现异常时给出原因和处理建议 |
| 每周总结 · 周五 17:00 | `0 17 * * 5` | 总结本周工作区中的重要进展、风险和待办 |

模板只预填名称、提示词和规则，**不会**直接创建任务。
</Step>

<Step>
### 填写三要素

| 字段 | 说明 |
| --- | --- |
| 绑定 Agent | 目标 Agent。编辑已有任务时不可改——换目标请新建 |
| 任务名称 | 列表里显示的名字，例如「每日工作摘要」 |
| 到期时发送给 Agent 的提示词 | 到期时原样发给 Agent 的那句话 |

名称和提示词都必填，留空会提示「请选择 Agent，并填写任务名称和提示词」。
</Step>

<Step>
### 选择触发方式

| 触发方式 | 参数 | 约束 |
| --- | --- | --- |
| 固定间隔 | 间隔秒数 | **最少 60 秒**；填小于 60 或非数字会按 3600 处理 |
| Cron | 五段表达式（时区 `Asia/Shanghai`）| 必须正好 5 个字段；支持 `*`、`,`、`-`、`/` |
| 执行一次 | 执行时间（本地时间）| 必须是**未来**时间，否则提示「请选择未来的执行时间」 |

Cron 例子：

```text
0 9 * * 1-5      工作日 09:00
*/30 * * * *     每 30 分钟
0 17 * * 5       周五 17:00
```
</Step>

<Step>
### 选择结果去向（云端）

云端自动化可以只留执行记录，也可以把结果发到渠道会话：

| 选项 | 行为 |
| --- | --- |
| 仅保存执行记录 | 结果留在「执行记录」里，不发送到任何 IM |
| 发送到渠道会话 | 从「收件会话」下拉里选一个 |

收件会话只列出**绑定了这个云端 Agent、且已完成过对话**的 WPS 协作或飞书会话，形如 `WPS · <渠道账号> · 群聊 <会话 ID>`。
列表为空通常意味着还没绑定渠道或还没跟机器人说过话。

<Callout type="info" title="发送失败不会重跑任务">
  投递是执行之后的独立一步。投递失败只会在执行记录上标一个投递状态，**不会**重新执行 Agent。
</Callout>
</Step>

<Step>
### 保存

点 **创建**（编辑时是 **保存修改**）。成功提示分两种：

- 本地：「本地自动化已创建，请保持应用运行。」
- 云端：「云端自动化已创建，关闭应用后仍按计划执行。」
</Step>

<Step>
### 日常管理

每个任务行上有：

| 操作 | 说明 |
| --- | --- |
| 详情 | 任务 ID、执行计划、会话方式、下次执行时间、完整提示词 |
| 执行记录 | 展开最近 8 次执行及状态 |
| 编辑 | 打开同一个表单 |
| 执行一次 | 立刻跑一次，**不改变**原有计划 |
| 删除 | 不可撤销。云端任务只停止后续触发，已触发的执行和结果投递会继续 |
| 启用开关 | 暂停 / 恢复。暂停的任务不能「执行一次」 |

看板视图按四列分组：**待执行**、**执行中**、**需关注**、**已暂停 / 已结束**。
</Step>

<Step>
### 看 DSH 原生会话自动化

本地页签下方有一个折叠区「DSH 原生会话自动化 N · 展开查看」。这些任务由**对话里的 `schedule_create`** 创建，与 Host Agent 自动化分开存储。

要创建一条，直接在新会话里说：

```text
每天 9 点提醒我整理工作摘要
```

DSH 会调用 `schedule_create`；创建后刷新本页就能看到。这里只读，编辑和删除回到原会话。
</Step>

</Steps>

## 调度语义

| 规则 | 行为 |
| --- | --- |
| 检查周期 | 每 **30 秒** 扫一次到期任务 |
| 错过触发 | 默认策略 `skip`：跳过本次，不补跑 |
| 同一任务并发 | 不允许。上个 occurrence 未结束时本次跳过 |
| 单实例占用 | 一个调度器独占存储目录；第二个进程启动会得到 `SCHEDULER_OWNED` |
| 进程崩溃恢复 | 启动时把 `claimed` / `running` / `accepted` / `admitting` 状态的旧执行统一标为失败，错误码 `AUTOMATION_OUTCOME_UNKNOWN`，**不重放**原调用 |
| 会话方式 | 每次新建会话（默认），或继续已有会话 |

`AUTOMATION_OUTCOME_UNKNOWN` 的含义是「原宿主执行中断，结果尚未确认，请通过原会话核对」——它不会自动补跑，必须人工确认。

## 成功后的样子

- 任务行徽章是 **已启用**，meta 里显示「下次执行：`<时间>`」。
- 点 **执行记录** 能看到最近的 occurrence，状态 `succeeded`，并带完成时间。
- 云端投递的任务在执行记录里显示「渠道投递：已送达」。
- 徽章变成 **需关注** 时，说明最近一次执行失败或投递失败，展开详情看 `errorCode` 与 `detail`。

## 常见错误

| 错误码 | 原因 | 处理 |
| --- | --- | --- |
| `SCHEDULE_KIND_INVALID` | `kind` 不是 `once` / `interval` / `cron` | 用界面上的三个触发方式之一 |
| `SCHEDULE_SPEC_INVALID` | `once` 缺 `at`，或 `interval` 缺 `everySeconds` | 补齐对应参数 |
| `SCHEDULE_TIMEZONE_INVALID` | 时区不合法 | 用 `Asia/Shanghai` |
| `CRON_INVALID` | Cron 不是 5 个字段 | 按上面的例子改成五段 |
| `TASK_ID_INVALID` | 任务 ID 不符合 `^[a-z][a-z0-9-]{2,62}$` | 让系统自动生成，不要手输 |
| `SCHEDULE_NOT_FOUND` | 任务不存在 | 刷新列表后重试 |
| `SCHEDULE_DISABLED` | 对已暂停的任务点「执行一次」 | 先启用再执行 |
| `SCHEDULE_RUNNING` | 该任务上一次执行还没结束 | 等它结束 |
| `SCHEDULER_CLOSED` | 调度器已关闭 | 重启应用 |
| `SCHEDULER_OWNED` | 另一个宿主进程正占用调度器 | 关掉另一个进程 |
| `AUTOMATION_OUTCOME_UNKNOWN` | 原宿主执行中断，结果未确认 | 到原会话核对；系统不会重放 |
| `AUTOMATION_RUN_FAILED` | 运行适配器执行失败 | 看执行记录的 `detail` |
| `delivery_target_unavailable` | 原渠道或会话已不可用 | 检查 Channels 里的绑定 |
| `delivery_target_changed` | 机器人或收件会话已变化 | 重新选择收件会话 |
| `delivery_conversation_missing` | 尚未取得会话信息 | 先与机器人对话一次 |
| `result_text_missing_or_too_large` | 本轮没有可发送文本，或结果超长 | 缩短提示词要求，或改为「仅保存执行记录」 |
| `delivery_outcome_unknown` | 发送进程未确认结果 | 到收件会话核对；不会自动重发 |
