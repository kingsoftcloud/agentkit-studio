## v0.0.24

### What you will notice

- **The overview supports continuing work.** Existing users see recent Agents, 24-hour activity, upcoming automation and workspace health, with one-click conversation navigation. Zero-Agent users see creation paths and a three-step guide instead of empty metrics.
- **First-time model setup is clearer.** Missing credentials or an unusable model now lead to explicit guidance. The model catalog adds context windows, vision support, reasoning levels and provider names, while budget saving and catalog probes are more reliable.
- **Model selection is richer.** RouteMind can provide model ratings, radar charts and relative prices; the Star Harness detail page retains signed versions, upgrades and rollback.
- **Interrupted tasks can resume.** An explicit resume instruction restores the original Star Harness Run and event cursor without repeating completed tool calls. TokenUsage remains available in native automation and Runtime Responses.
- **Unreachable KSXC no longer misleads.** Internal runtime entries disappear while the gateway is unreachable and return after recovery; existing KSXC Agents remain editable with their model bindings intact.
- **Cloud instances no longer stall on YAML formatting.** ManagedRuntime compares parsed declarations. Genuine drift now moves to `ACTION_REQUIRED` for repair instead of leaving the instance stuck at provisioning.

### Upgrading

There are no breaking changes. This release also updates the overview, DSH Native, configuration reference and release documentation in both languages.

## v0.0.16

### What you will notice

- **Images stop disappearing.** Sent images survive thumbnails, the lightbox, and a history refresh; image-only messages render too.
- **Turn durations are accurate.** Answer-only turns use committed start/end times instead of network jitter.
- **Each workspace talks to its own Harness.** Switching between Alpha and Beta keeps model, working directory, and history separate.
- **Entry copy changed.** "Manual configuration" now lives under **More ways to create**; runtime selection is a radio group, not a dropdown.
- **Process output is collapsed by default.** Failed turns show a neutral summary; expand for the full reason. Usage is pinned under the composer.

### Breaking changes

| Change | Impact | What to do |
| --- | --- | --- |
| In-process Harness removed | Custom deployments relying on in-process execution fail | Use a standalone Harness service or an explicit external command |
| Old `sessions/native-*` control routes deleted | Integrations calling them get `STUDIO_LEGACY_HARNESS_RETIRED` | Migrate to the new routes |
| Three `bundledDependencies` removed | The npm package no longer inlines Harness Core/Node/UI | Declare the dependencies explicitly |
| `publishConfig.executableFiles` removed | Local-process launchers no longer ship in the package | Do not depend on an in-package launcher |
| Unbound directories are refused | No fallback to another project | Complete the workspace binding |

Full steps in [upgrade to v0.0.16](./upgrade-to-0.0.16.mdx).

## v0.0.15

| What you will notice | Details |
| --- | --- |
| Tasks reach the standalone service | Native sessions, Team roles, and bound A2A tasks all execute there; the desktop reconnects to the original Run |
| Unified interface | The agent form collapses to three steps; resource library, delivery, and operations share DSH design tokens |
| New agents default to DSH Native | Star Harness is hidden from creation (editing existing Star Harness agents still works) |
| Denser MCP resource page | "Auth headers / environment credentials" folds into an advanced section that auto-expands for custom headers |
| Light-theme buttons are readable | Primary button hover no longer flips the white label to a light background |
| Deployment details show image tags | Update checks split into current and target image (tag + digest) |

Internal changes you will not operate directly: managed Codex timeout variables added to the env whitelist, the Hosted UI session
registry moved to agent scope, frozen-host MCP turn budget raised to 15 minutes (adjustable via `AGENTKIT_RUNTIME_TIMEOUT_MS`),
and the browser bundle size became a gate.

## v0.0.14

| What you will notice | Details |
| --- | --- |
| The plugin market can discover | Aggregates npm `keywords:dsh-plugin` and GitHub `topic:dsh-plugin` with category filters, download/star sorting, detail cards, one-click install |
| Updates no longer hop version by version | Every publication mirrors the same feed onto the compatibility lane, so historical installs jump straight to the newest release |
| Long sessions compress less often | The model context window reads `context_length` from the model gateway `/v1/models` instead of a fixed 128000 |
| Incompatibility is explained | When a cloud image catalog declares an unimplemented capability, only that image is retired and the latest compatible one is used |
| Cloud Codex runs full-access by default | The container is already the isolation boundary; Codex's own sandbox cannot start on a read-only rootfs. Narrow it with `AGENTKIT_CODEX_SANDBOX` |
| Partially unavailable resources still chat | Degraded operation is the default; `AGENTKIT_STRICT_RESOURCES=1` restores fail-closed |

## Should you upgrade?

| Your situation | Recommendation |
| --- | --- |
| You run a custom in-process Harness | Read [upgrade to v0.0.16](./upgrade-to-0.0.16.mdx) first |
| You only author agents locally | Upgrade directly; no breaking impact |
| You rely on the plugin market | 0.0.14 or later, where discovery exists |
| You need multi-workspace isolation | Requires 0.0.16 |
