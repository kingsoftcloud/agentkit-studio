## Ordering and pairing

```text
turn/start → request/header → request/context → step/start
  → assistant/attempt → (tool/call → approval/asked → approval/decided → tool/result)*
  → step/end → assistant/message → turn/end
```

| Event | Ordering rule |
| --- | --- |
| `turn/start` | The single entry point of a turn. |
| `turn/end` | The only guaranteed terminal event; its absence means the connection dropped. |
| `step/start` | A step carries at least one `assistant/attempt`. |
| `step/end` | Pairs one-to-one with `step/start`. |
| `system/message` | May appear anywhere without changing turn state. |
| `request/header` | Follows `turn/start`; once per turn. |
| `request/context` | Follows `request/header`. |
| `user/message` | Usually once at the start of a turn. |
| `assistant/message` | At most one per turn, from the last attempt. |
| `assistant/attempt` | Repeats within a turn when retried. |
| `tool/call` | Pairs with `tool/result` by call id. |
| `tool/result` | Always after the matching `tool/call`. |
| `approval/asked` | Only when a tool needs authorization. |
| `approval/decided` | Must pair with `approval/asked`. |
| `agent/inbox/spliced` | Signals concurrent writes; projections must merge in order. |
| `agent-preset/selected` | Usually before a turn starts. |
