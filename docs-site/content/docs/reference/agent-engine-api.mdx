**这一页讲的是「部署到云端之后，怎么用 HTTP 调它」。它和参考章里的 [控制协议](./operations.mdx) 不是同一套东西。**

| | Studio RPC | AgentEngine Action（本页） |
| --- | --- | --- |
| 谁和谁说话 | 浏览器 ↔ 本地 Host | 本地 Host ↔ 云控制面 |
| 规模 | `146` 个 operation | `43` 个 Action + `5` 个 Skill 服务 Action |
| 通道 | `/agentkit` | `POST /agentengine/api/v1/{Action}` 或 KOP `/?Action=…&Version=v1` |
| 信封 | `{ ok, value }` / `{ ok, error }` | `{ Code, RequestId, Error, Data }` |
| 认证 | 本地 Host 会话 | `Authorization: Bearer` 或 AWS SigV4 |

把两者混用是本页最常见的错误：Studio RPC 的 operation id 不是云侧 Action 名，反过来也不成立。

## 三层地址，别混

| 层 | 地址形状 | 用途 | 形状校验 |
| --- | --- | --- | --- |
| Studio RPC | 本地 Host 端口 | 浏览器驱动本地 Host | — |
| 控制面 KOP | `https://aicp.api.ksyun.com` （公网）<br />`<inner-kop-host>` （内网，通常是 `http://`） | Host 调云侧 `43` 个 Action | 必须是干净的 origin：带端口、userinfo、query 或非根 path 一律 `SERVER_URL_INVALID` (`src/server-client.mjs:507`) |
| 运行时端点 | `https://<AgentId>.agent.kspmas.ksyun.com` | 调**已部署 Agent** 的 `/v1/responses`、`/health`、`/v1/agentkit/runtime` | 只校验公网形状 (`src/studio-deployments.mjs:47-49`) |

<Callout type="warn" title="内网地址没有形状校验">
内网运行时地址（以及部分账号只能走的 `<inner-kop-host>`）**没有形状校验**——那是控制台与网关侧的能力，SDK 不做判断。本页不声称「SDK 会校验内网地址」。
</Callout>

## 端点发现

**推荐路径（人来看）**：AICP 控制台 → 部署详情 → 复制端点。公网地址和内网地址都会展示，同时能拿到 API Key。

**程序化路径（代码来取）**：`GetAgent` 返回的部署记录里带两种形态，按顺序回退 (`src/studio-deployments.mjs:44-46`)：

| 字段 | 何时有 |
| --- | --- |
| `Network.PublicEndpoint` | 网络已就绪的部署 |
| `QuickAccess.PublicEndpoint` | 快速访问入口 |

`QuickAccess.ApiKey` 是运行时令牌 (`src/studio-deployments.mjs:381,445,511`)，用它换运行时端点的访问权。

身份探针：`GET /v1/agentkit/runtime` (`src/build-runtime-http.mjs:99`) 返回运行时身份与执行策略；`GET /health` 返回 `{ status: "ready" | "stopping" }` (第 95 行)。

## 认证

两条路由的认证方式**完全不同**，不要互相套用。

| 项 | 自定义 Server | KOP (AICP 网关) |
| --- | --- | --- |
| 凭证 | 服务令牌 | 子账号 AK/SK |
| 主 Header | `Authorization: Bearer <token>` | `Authorization` 由 AWS SigV4 生成 |
| 签名 | — | SigV4, `service=aicp`, `region=cn-beijing-6` |
| 会话头 | loopback 时加 `X-AgentKit-Session` | — |
| 必带头 | `X-Ksc-Request-Id`、`X-Ksc-Region`、`X-Ksc-Source` | 同上 + `X-Action`、`X-Version` |
| 可选头 | — | `X-Ksc-Account-Id`、`X-Ksc-User-uuid` |
| 预发（pre-online） | — | 额外 `X-KSC-CUSTOM-SOURCE: pre` |
| 请求体 | 原样 payload | 额外带 `Service`、`Action`、`Version`、`SdkVersion`、`Region`、`Accesskey` |

<Callout type="warn" title="内网回退只对 403 生效">
公网 IAM 返回 **403 且报文含 `inner account`** 时，客户端会改走内网 IAM 重试一次（`src/cloud-identity.mjs:82-83`、`src/server-client.mjs:556`）。这是**端点选择**，不是对写请求的重试——其他 4xx 一律不重试。
</Callout>

## 两条调用路径，body 不同

调「已部署的 Agent」有两条路，**请求体形状不一样**，混用会得到 400 或空响应：

| | 控制面 RunAgent | 运行时 /v1/responses |
| --- | --- | --- |
| 地址 | `POST {controlPlane}/agentengine/api/v1/RunAgent` (KOP: `POST /?Action=RunAgent&Version=v1`) | `POST https://<AgentId>.agent.kspmas.ksyun.com/v1/responses` |
| 认证 | `Authorization: Bearer` 或 AWS SigV4 | `Authorization: Bearer <runtime-token>` |
| 字段风格 | PascalCase | snake_case |
| 谁在用 | Host 的本地会话桥 (`src/host/routes/http.mjs:110-113`) | 直连部署的 Agent (`src/deployment-conversation.mjs:26-27,99`) |

### 控制面 RunAgent

字段来自 `src/host/routes/http.mjs:110-113`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `AgentId` | string | 是 | 已部署的 Agent 标识 |
| `SessionId` | string | 是 | 云侧会话标识，缺失报 `INVALID_CONVERSATION_INPUT` |
| `Messages` | array | 是 | `[{ role: 'user', content: string }]` |
| `Stream` | boolean | 是 | 固定 `true`；流式是唯一支持形态 |
| `ApiFormat` | string | 是 | 固定 `'responses'`，走 OpenAI Responses 兼容帧 |
| `InvocationId` | string | 否 | 幂等键，见 [超时与重试](#超时与重试) |

```sh
curl -N "https://aicp.api.ksyun.com/agentengine/api/v1/RunAgent" \
  -H "Authorization: Bearer <service-token>" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -H "X-Ksc-Request-Id: $(uuidgen)" \
  -H "X-Ksc-Region: cn-beijing-6" \
  -H "X-Ksc-Source: agentkit-studio" \
  -d '{
    "AgentId": "<AgentId>",
    "SessionId": "<SessionId>",
    "Messages": [{ "role": "user", "content": "list the files in this workspace" }],
    "Stream": true,
    "ApiFormat": "responses",
    "InvocationId": "'"$(uuidgen)"'"
  }'
```

### 从公网调用 DSH ManagedRuntime

用 Agent API Key 调用 `POST {PublicEndpoint}/agentengine/api/v1/RunAgent`。请求使用 `ApiFormat: "responses"` 与本轮 `ResponsesInput`。

| 字段 | 用途 |
| --- | --- |
| `SessionId` | 平台会话 ID。取自 CreateSession 的 Data.Session.SessionId，或首轮 RunAgent 响应的 session_id。续聊时保持不变。 |
| `InvocationId` | 每轮一个新 ID；同一轮重试保留原 ID。 |
| `UserId` | 可选的 MCP 业务用户 ID；平台授权仍以认证主体为准。 |
| `BusinessSessionId` | 可选的 MCP 业务会话 ID，不用于续聊。与平台 SessionId 分开。 |

Server 转发这两个业务字段，Host 通过工具请求的 _meta 和 HTTP 请求头传给绑定的 MCP 服务。后续轮次可以省略已绑定的字段；模型与会话历史不会收到这些业务 ID。

### 运行时 /v1/responses

字段来自 `src/deployment-conversation.mjs:26-27`。注意 `session_id` 与 `request_id` 都由调用方从原始标识**确定性派生**，不是随机值——这样重发同一轮才能被认成同一请求：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `input` | string | 是 | 本轮用户输入 |
| `stream` | boolean | 是 | 固定 `true` |
| `model` | string | 是 | 绑定模型名，必须与冻结版本一致 |
| `session_id` | string | 是 | `studio-` 加 `sha256(sessionId)` |
| `request_id` | string | 是 | `message-` 加 `sha256(JSON.stringify([sessionId, messageId]))` |
| `x-agentkit-permission-mode` | header | 否 | 只在冻结镜像声明了允许模式时携带 (第 34-35 行) |

```js
const sha = (value) => createHash('sha256').update(value).digest('hex').slice(0, 40);

const response = await fetch(`https://${agentId}.agent.kspmas.ksyun.com/v1/responses`, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${runtimeToken}`,
    'Content-Type': 'application/json',
    Accept: 'text/event-stream',
  },
  body: JSON.stringify({
    input: userText,
    stream: true,
    model,
    session_id: `studio-${sha(sessionId)}`,
    request_id: `message-${sha(JSON.stringify([sessionId, messageId]))}`,
  }),
  redirect: 'error',
});
if (!response.ok || !response.headers.get('content-type')?.includes('text/event-stream')) {
  throw new Error(`cloud conversation rejected (HTTP ${response.status})`);
}
```

## 消费 SSE 流

响应是 `text/event-stream`，帧格式是 OpenAI `responses` 兼容的，**不是** Action 的 JSON 信封：

| 帧 | 含义 |
| --- | --- |
| `response.created` | 本轮开始，带 `runId` |
| `response.output_text.delta` | 正文增量，追加拼接 |
| `response.output_item.added` | 出现一个工具调用或消息项 |
| `response.completed` | 本轮完成，带用量 |
| `response.failed` | 本轮失败，带错误摘要 |

```js
const reader = response.body.pipeThrough(new TextDecoderStream()).getReader();
let buffer = '';
for (;;) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += value;
  const frames = buffer.split('\n\n');
  buffer = frames.pop() ?? '';
  for (const frame of frames) {
    const data = frame.split('\n').filter((line) => line.startsWith('data:')).map((line) => line.slice(5).trim()).join('');
    if (!data || data === '[DONE]') continue;
    const event = JSON.parse(data);
    if (event.type === 'response.output_text.delta') process.stdout.write(event.delta ?? '');
    if (event.type === 'response.failed') throw new Error(event.response?.error?.message ?? 'run failed');
  }
}
```

<Callout type="info" title="Stream 和 ApiFormat 都不能省">
`Stream: true` 决定响应是 SSE 而不是 JSON；`ApiFormat: 'responses'` 决定帧是 Responses 形状。少任何一个，客户端都会按错误的解析器读响应。
</Callout>

## 错误信封与错误码

成功与失败都是同一个信封 (`src/server-client.mjs:420-431`)：

```json
{
  "Code": 0,
  "RequestId": "<request-id>",
  "Data": {},
  "Error": null
}
```

判定规则：`Code` 为 `0` 或 `200` 且没有 `Error` 才算成功；少数资源类 Action（如 `ListSessions`）允许 `Code` 缺省。失败时客户端抛出 `AgentEngineError`，把 `RequestId` 一起带出来。

| 错误码 | 触发条件 | 客户端该做什么 | 抛出处 |
| --- | --- | --- | --- |
| `SERVER_ACTION_FAILED` | 云端返回非 0/200 的 Code 或 `Error` 字段 | 读 `RequestId` 找云侧日志；不要原样重试写请求 | `src/server-client.mjs:434` |
| `SERVER_ACTION_NOT_REGISTERED` | KOP 报 `InvalidActionOrVersion`，该 Action 未在该环境发布 | 确认环境与 API 版本；发布后再重试 | `src/server-client.mjs:427` |
| `SERVER_URL_INVALID` | 控制面地址不是 HTTPS origin，或带端口/userinfo/query | 只传 origin；HTTP 仅限本机或运行时配置的内网入口 | `src/server-client.mjs:507` |
| `SERVER_CREDENTIALS_MISSING` | 自定义 Server 是非 loopback 但没配服务令牌 | 配置 `cloudServiceToken` | `src/server-client.mjs:392` |
| `SERVER_UNAVAILABLE` | 请求未完成（连接失败或超时） | 检查网络；写请求不会自动重试 | `src/server-client.mjs:404` |
| `SERVER_INVALID_RESPONSE` | 响应体不是合法 JSON | 检查网关/代理是否改写了响应 | `src/server-client.mjs:418` |
| `SERVER_RATE_LIMITED` | 上游返回 429 | 退避后重试；流式请求同样受限 | `src/server-client.mjs:434` |
| `ACTION_NOT_ALLOWED` | 该 Action 不在 `SERVER_ACTIONS` 白名单里 | Studio 不开放这个 Action，换受支持的动作 | `src/server-client.mjs:348` |
| `CLOUD_CREDENTIALS_MISSING` | KOP 路由需要 AK/SK 但没配置 | 设置 → 模型与凭证 → 云端配置 | `src/server-client.mjs:375` |
| `CLOUD_SUBACCOUNT_REQUIRED` | 创建类 Action 用了主账号 AK/SK | 改用已核验的子账号 AK/SK | `src/server-client.mjs:357` |
| `REQUEST_CANCELLED` | 调用方 AbortSignal 已触发 | 这不是失败，按取消处理 | `src/server-client.mjs:404` |
| `SKILL_SERVICE_FAILED` | Skill Service 返回非 0/200 | 同上：读 `RequestId` 定位 | `src/server-client.mjs:492` |
| `SKILL_SERVICE_UNAVAILABLE` | Skill Service 需要 AICP 云端凭证但当前不是 KOP 路由 | 切到 KOP 云端凭证 | `src/server-client.mjs:457` |

## 超时与重试

两个窗口分开，因为流式请求会在托管运行时准入上花更久（`src/server-client.mjs:537-540`  注释）：

| 场景 | 默认超时 | 依据 |
| --- | --- | --- |
| 普通 JSON Action | 15 秒 | `timeoutMs = 15000` |
| 流式 `RunAgent` | 180 秒（取两者较大值） | `streamTimeoutMs = Math.max(timeoutMs, 180000)` |

<Callout type="error" title="写请求不会自动重试">
`SERVER_UNAVAILABLE` 的文案里写死了「写请求不会自动重试」——因为客户端无法判断上游是否已经受理。要做幂等，靠调用方自己传键：

| 键 | 作用域 | 依据 |
| --- | --- | --- |
| `InvocationId` | 一次 `RunAgent` | `src/host/routes/http.mjs:113` |
| `X-Ksc-Request-Id` | 一次 HTTP 请求 | `src/server-client.mjs:378` |

同一个 `InvocationId` 重发，云端才能把两次请求认成同一轮。**不要**用随机值伪装重试——那等于两次独立提交。
</Callout>
