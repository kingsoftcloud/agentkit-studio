## 轮询态

这些状态代表「平台还在做事」，客户端可以安全重试轮询：

| 状态 | 界面标签 |
| --- | --- |
| `UPDATING` | 切换版本 · 等待入口确认 |
| `UPDATE_UNKNOWN` | 更新结果待核对 |
| `PROVISIONING` | 准备实例 |
| `CONFIGURING` | 配置访问令牌 |
| `TOKEN_PENDING` | 等待配置生效 |
| `STARTING` | 启动中 |
| `AVAILABLE_UPDATING` | 入口可用 · 平台更新中 |
| `DELETING` | 删除中 |
| `DELETE_UNKNOWN` | 删除结果待核对 |

## 需关注态

这些状态代表「结果不确定或需要人」，继续轮询不会改变结果：

| 状态 | 界面标签 |
| --- | --- |
| `CREATE_UNKNOWN` | 创建结果待核对 |
| `UPLOAD_UNKNOWN` | 上传结果待核对 |
| `UPDATE_UNKNOWN` | 更新结果待核对 |
| `DELETE_UNKNOWN` | 删除结果待核对 |
| `ACTION_REQUIRED` | 需要处理 |
| `FAILED` | 失败 |
| `TOKEN_PENDING` | 等待配置生效 |

<Callout type="warn" title="结果待核对不等于失败">
带 `*_UNKNOWN` 后缀的状态表示上一次请求的结果未知。先核对云端实际状态，再决定重试还是回滚；直接重试可能产生第二个资源。
</Callout>

## 状态机主干

```text
PREPARED → UPLOADING → UPLOADED → CREATING → PROVISIONING → CONFIGURING
        → TOKEN_PENDING → STARTING → READY
READY → UPDATING → AVAILABLE_UPDATING → READY
any state → FAILED | ACTION_REQUIRED
any state → DELETING → DELETED
```

主干之外只有两条支线：失败与删除。所有 `*_UNKNOWN` 都是主干某一步的中断记录，不是独立分支。
