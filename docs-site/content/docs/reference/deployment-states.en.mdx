## Attention states

These states mean the outcome is unknown or needs a human; more polling will not change them:

| State | UI label |
| --- | --- |
| `CREATE_UNKNOWN` | 创建结果待核对 |
| `UPLOAD_UNKNOWN` | 上传结果待核对 |
| `UPDATE_UNKNOWN` | 更新结果待核对 |
| `DELETE_UNKNOWN` | 删除结果待核对 |
| `ACTION_REQUIRED` | 需要处理 |
| `FAILED` | 失败 |
| `TOKEN_PENDING` | 等待配置生效 |

<Callout type="warn" title="Unknown is not failed">
A `*_UNKNOWN` state means the last request has an unknown outcome. Reconcile against the cloud side before retrying or rolling back; a blind retry can create a second resource.
</Callout>

## Happy path

```text
PREPARED → UPLOADING → UPLOADED → CREATING → PROVISIONING → CONFIGURING
        → TOKEN_PENDING → STARTING → READY
READY → UPDATING → AVAILABLE_UPDATING → READY
any state → FAILED | ACTION_REQUIRED
any state → DELETING → DELETED
```

Only two branches leave the happy path: failure and deletion. Every `*_UNKNOWN` state is an interrupted step on the happy path, not a separate branch.
