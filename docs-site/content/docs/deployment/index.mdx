**运行时（runtime）决定一次「模型 + 工具」循环由哪个进程执行。** Studio 不实现这个循环，它把 Agent 修订版本路由到三种运行时之一，并只在循环外侧负责会话归属、资源绑定与审批。

## 三种 `runtime.type`

| `runtime.type` | 界面名称 | 循环归属方 | 新建 Agent 时可选 |
| --- | --- | --- | --- |
| `dsh-native` | DSH Native Harness | DSH 原生循环 | 是（默认） |
| `harness` | Star Harness | Harness 原生内核 | 仅编辑既有 Agent |
| `codex` | Codex Agent | Codex App Server | 是 |

`STUDIO_RUNTIME_TYPES` 就是这三个值（`src/runtime-contract.mjs:6`），创建表单渲染的 `ALLOWED_RUNTIME_TYPES` 也是同一组（`src/client/theme.mjs:26`）。

<Callout type="warn" title="Star Harness 需要先装好才能选">
  `creatableRuntime` 对 `harness` 额外要求 `starHarnessReady`，它来自 `star-harness/status` 的 `canCreate`——即**已安装 + 已启用 + 至少一个可用工作区**三者同时成立（`src/client/pages/agent-form.mjs:61-79`、`src/host/services/star-harness.mjs:150`）。没装好之前，新建表单只列出 **DSH Native Harness** 与 **Codex Agent**；编辑既有 Star Harness Agent 则始终可选。
</Callout>

## 该选哪一条

| 你的情况 | 选择 | 原因 |
| --- | --- | --- |
| 不知道选什么 | `dsh-native` | 默认授权运行时（`src/authoring-defaults.mjs:4`），装配成本最低 |
| 需要多角色协作与可配置工具循环 | `harness` | 能力集含 `child-tasks`、`resume`、`durable-receipts`（`src/runtime-contract.mjs:25-29`） |
| 任务主要是改代码、跑命令 | `codex` | 独立进程 + Codex App Server，与 DSH 会话共享（`src/providers/codex-runtime.mjs:1-8`） |
| 云端常驻、由平台声明定义 | 托管运行时 | 见[托管运行时生命周期](./managed-runtime-lifecycle.mdx) |

## 运行时如何限制部署能力

选运行时不是纯本地的决定——它决定了这个 Agent 能不能进便携包、能不能被平台声明驱动。

| 运行时 | 进便携包 / 部署 | 托管声明里的 `framework` | 依据 |
| --- | :--: | --- | --- |
| `dsh-native` | 是 | `dsh-native` | `src/managed-runtime-manifest.mjs:11` |
| `harness` | 是 | `harness` | 同上 |
| `codex` | 是 | `codex` | 同上 |

托管声明的 `runtimes` 白名单与 `STUDIO_RUNTIME_TYPES` 是同一组三个值（`src/managed-runtime-manifest.mjs:11`），所以一份合法声明只可能落在三种运行时之一。

## 三条路径的失败语义不同

| 运行时 | 谁拥有 Run 账本 | 失败后能否原地恢复 |
| --- | --- | --- |
| `dsh-native` | DSH Session | 靠会话历史重开，无 Run 断点 |
| `harness` | Harness 原生 Run 账本 | 支持 `resume`，可跨进程续跑 |
| `codex` | DSH Session | 靠会话历史重开；取消是协作式的 |

这也是为什么选型时真正要看的是「谁拥有状态」，而不是「谁的功能列表更长」（详见[三运行时对照](./runtimes-compare.mdx)）。

## 两条部署形态

| 形态 | 入口 | 状态归属 | 典型用途 |
| --- | --- | --- | --- |
| 本地 / 桌面 | DSH 进程内 | 本机磁盘 | 开发与日常使用 |
| 托管运行时 | 平台 YAML 声明 | 平台 VersionId | 7×24 云端常驻 |

托管形态不重新打包 Studio，也不在容器里编辑 Agent：声明由平台版本管理，容器内对 Agent 的写操作一律返回 `MANAGED_RUNTIME_READ_ONLY`（`src/managed-runtime-definition.mjs:79`）。
