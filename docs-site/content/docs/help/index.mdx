## 先做这三件事

在翻文档之前，这三步能解决大半问题：

<Steps>
<Step>
### 看「启动检查」

**总览 → 启动检查**，展开后会跑三项并给三态结论（`src/client/state/start-checks.mjs:22-26`）：

| 结论 | 含义 |
| --- | --- |
| 已确认 | 读到了真实配置 |
| 缺少配置 | 明确没配，按提示去补 |
| 未知 | 读不到（超时 / 连接失败），不是「没配」 |

三项都有 8 秒超时。全是「未知」说明 Host 根本没连上，先解决连接问题。
</Step>

<Step>
### 核对版本

**设置 → AgentKit Studio → 版本与更新**，确认三个版本号（`src/client/pages/studio-settings.mjs:78-80`）：

- **AgentKit Studio 版本** —— 桌面应用版本
- **Studio 插件版本** —— 产品功能与运行适配层版本
- **DSH 宿主兼容版本** —— 固定宿主基线

三者不是同一个东西。报 issue 时三个都要给。
</Step>

<Step>
### 复现一次

关掉工作室重开，从干净状态复现。如果只在「跑了几轮之后」出现，多半和会话历史或运行时状态有关，记下是第几轮。
</Step>
</Steps>

## 提 issue 需要什么

信息不全的 issue 只能来回问。请直接给出：

| 需要的信息 | 从哪拿 |
| --- | --- |
| 三个版本号 | 设置 → AgentKit Studio → 版本与更新 |
| 平台与架构 | macOS（Apple Silicon）/ Windows（x64） |
| 完整错误码 | 卡片上的错误文案，或 observability 里的 trace |
| 复现步骤 | 从哪个面板、点了什么、输入了什么 |
| 运行中心记录 | 运行中心 → 观测 → 对应 Trace 的 Span 与事件 |
| 是否云端 | 本地 Host 还是云端托管运行时 |

<Callout type="warn" title="不要贴凭证">
截图和日志里请自行遮住 API Key、AK/SK、Cookie 与私有地址。
Studio 展示历史时会自动把常见凭证形态替换成 `[已隐藏凭据]`（`src/dsh-history-display.mjs:10-21`），但**截图和终端输出不在此列**。
</Callout>

## 自检命令

源码或插件形态可以用这几条自查：

```sh
# 插件形态：确认宿主版本
dsh --version

# 源码形态：跑门禁
pnpm install --frozen-lockfile
make check

# 看 Node 是否达到安全基线
node scripts/check-node-version.mjs
```

`make check` 覆盖语法、可移植性、源码体积、契约与产品面检查（`Makefile:71-72`）。它失败时给出的路径就是问题所在。
