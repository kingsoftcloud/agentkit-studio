Studio 的错误码全部来自 `src/**` 里的 `code: '...'` 字面量，可以直接在源码里搜。这一页按**出错位置**分组，同一个错误码只出现一次。

<Callout type="info" title="先确认错误码是不是真的错误码">
界面上的错误文案有时是自然语言，错误码在被折叠的详情里。展开工具卡片、或到 **运行中心 → 观测** 看 Trace，能拿到原始 `code` 与 HTTP 状态。
</Callout>

## 模型与凭证

| 症状 | 错误码 | 原因 | 处理 |
| --- | --- | --- | --- |
| 发消息立刻失败，提示去配 Key | `MODEL_CREDENTIAL_MISSING` | 模型配置没有可用的 API Key（`src/model-service.mjs:71,116`） | 设置 → 模型与凭证，选中模型填 Key 后保存 |
| 选了模型但请求打到空 | `MODEL_NOT_FOUND` | 模型配置不存在、已停用，或不在网关目录中（`model-service.mjs:61`） | 在「默认模型」里重选；网关模式先刷新模型目录 |
| 保存模型时报地址无效 | `MODEL_ENDPOINT_INVALID` | 服务地址不是合法 URL（`src/model-endpoint.mjs:9`） | 补全 `https://` 与主机名 |
| 同上，但报的是协议 | `MODEL_URL_INVALID` | 只接受 `https:` 端点（`model-service.mjs:37`） | 换成 HTTPS 端点，本地调试用 localhost 代理 |
| 保存后模型列表为空 | `MODEL_PROFILE_INVALID` | 模型名称、模型 ID 或凭证引用三者有一项无效（`model-service.mjs:34`） | 重新「读取模型目录」，从目录里选而不是手打 |
| 想重名保存被拒 | `MODEL_PROFILE_EXISTS` | 模型资源名称已被占用（`model-service.mjs:41`） | 换一个名称 |
| 「读取模型目录」失败 | `MODEL_CATALOG_FAILED` | 目录接口返回非 2xx（`model-service.mjs:89`） | 检查端点、Key 与出网策略；错误文案带状态码 |
| 云端资源页空 | `CLOUD_CREDENTIALS_MISSING` | 没配云端 AK/SK（`src/server-client.mjs:361,462,519`） | 设置 → 模型与凭证 → 云端配置，填 AK/SK |
| 请求被 413 拒绝 | `REQUEST_TOO_LARGE` | 模型请求体超过 16 MiB（`src/model-proxy-handler.mjs:47`） | 减少附件、缩短历史，或拆成多轮 |
| 回答只出了一半就断 | `UPSTREAM_STREAM_TRUNCATED` | 上游模型流没返回完成标记就断开（`model-proxy-handler.mjs:150`） | 重试；持续出现时检查代理/网关的空闲超时 |
| 兼容端点要求重传历史 | `STATELESS_INPUT_REQUIRED` | 该端点不保存远端 Response ID（`model-proxy-handler.mjs:55`） | 客户端必须每轮传完整对话历史 |
| 选 Codex 模型被拒 | `CODEX_AGENT_REQUIRED` | 没有绑定 Codex Agent（`src/providers/dsh-runtime.mjs:585`） | 先在 Agent 上绑定 Codex 运行时，再选模型 |

## Agent 与构建

| 症状 | 错误码 | 原因 | 处理 |
| --- | --- | --- | --- |
| 会话里发消息失败 | `STUDIO_AGENT_REQUIRED` | 当前会话没有绑定 Agent（`dsh-runtime.mjs:604`） | 从智能体面板选中一个 Agent 再发 |
| 发送按钮点了没反应 | `STUDIO_INPUT_REQUIRED` | 输入为空且没有图片（`dsh-runtime.mjs:605`） | 输入文字或附加图片 |
| 编辑后保存报「不存在」 | `AGENT_NOT_FOUND` | 本地 Agent 已被删除或 ID 漂移（`src/host/routes/agents.mjs:13`） | 刷新智能体列表后重选 |
| 请求缺参数 | `INVALID_AGENT_ID` | `AgentId` 为空（`agents.mjs:52`） | 从列表进入，不要手拼 URL 或命令 |
| 部署/运行被拒 | `BUILD_NOT_READY` | Agent 还没有可运行的 Build（`src/host-remote.mjs:166`） | 先创建 Build 并等它完成 |
| 冻结会话创建失败 | `STUDIO_PRESET_RUNTIME_UNSUPPORTED` | 当前 runtime 没有 DSH 原生会话适配器（`src/agent-preset-admission.mjs:161`） | 换成 `dsh-native` 运行时再冻版本 |
| 老会话打不开 | `DSH_PRESET_ROUTE_UNAVAILABLE` | 会话原有的 Agent 运行预设不可用（`agent-preset-admission.mjs:343`） | 重新绑定运行时；不要试图恢复已删除的预设 |
| MCP 工具调用失败 | `STUDIO_NATIVE_MCP_SCHEMA_ENGINE_REQUIRED` | 会话的 MCP 工具 schema 引擎不可用（`src/providers/dsh-runtime-plugin.mjs:209`） | 「请重新绑定当前会话的 MCP 工具」 |
| 模型要调一个不存在的工具 | `TOOL_NOT_FOUND` | DSH Tool 未注册，或不在当前 Agent 绑定范围（`dsh-runtime-plugin.mjs:173`） | 在 Agent 编辑页补绑该 Tool，或改提示词 |

## 运行时

| 症状 | 错误码 | 原因 | 处理 |
| --- | --- | --- | --- |
| 全程无响应 | `HOST_CONNECTION_MISSING` | Studio 本地任务需要已连接的 Studio Host（`src/remote/control-client.mjs:144`） | 看右上角状态胶囊；重启 Host 后重试 |
| 插件加载被拒 | `STUDIO_HOST_INCOMPATIBLE` | 宿主版本不满足 `engines.dsh`（`src/host/compatibility.mjs:40`） | 升级到固定的 DSH 基线 `0.2.2-rc.1` |
| 托管会话起不来 | `NATIVE_ENGINE_UNAVAILABLE` | 托管 Native Harness 需要独立服务绑定（`src/host/bootstrap.mjs:406`） | 配置并启动独立的 Harness 服务 |
| 报「没有绑定独立 Harness」 | `NATIVE_ENGINE_WORKSPACE_UNAVAILABLE` | 当前工作区没绑定独立 Harness（`agent-preset-admission.mjs:335`） | 换到已配置的工作区 |
| Harness 配置报错 | `NATIVE_ENGINE_CONFIG_INVALID` | 工作区、服务地址、凭据或预览地址有一项无效（`src/providers/engine-service-workspaces.mjs:57`） | 逐项核对四项配置 |
| Native 引擎要模型 | `NATIVE_ENGINE_MODEL_UNAVAILABLE` | 需要已配置接口地址的模型（`dsh-runtime.mjs:629`） | 在 Agent 上绑定网关模型 |
| 一轮跑完是失败 | `DSH_TURN_FAILED` | 运行时本轮未完成（`src/dsh-history-display.mjs:6`） | 重试；持续失败看模型与工具连接 |
| 老的进程内会话操作 | `LOCAL_HARNESS_RETIRED` | 进程内 Harness 已退役（`src/host/routes/http.mjs:24`） | 改用 Native Harness 会话 |
| 同上，另一入口 | `STUDIO_LEGACY_HARNESS_RETIRED` | 该操作属于已退役的进程内 Harness 会话（`src/host/routes/sessions.mjs:8`） | 重新创建 Native 会话 |
| 冻结版本跑不动 | `RUNTIME_MODEL_UNAVAILABLE` | 冻结模型没有可用的运行时路由（`src/frozen-build-runtime.mjs:72`） | 重新构建，让模型进入冻结绑定 |
| 冻结版本报模型不符 | `RESPONSES_FROZEN_MODEL_MISMATCH` | 请求的模型不在冻结绑定中（`frozen-build-runtime.mjs:88`） | 用冻结时绑定的模型发请求 |
| 宿主能力不足 | `RUNTIME_HOST_CAPABILITY_UNAVAILABLE` | 冻结运行时需要支持请求指纹的 DSH 宿主（`frozen-build-runtime.mjs:58`） | 升级宿主 |
| 自动化跑不起来 | `AUTOMATION_SERVICE_UNAVAILABLE` | 自动化需要的 DSH 服务未启动（`src/native-automation-runner.mjs:32`） | 按提示启动对应服务 |
| 自动化卡住 | `AUTOMATION_TIMEOUT` | 自动化运行超时（`native-automation-runner.mjs:85`） | 缩短任务或拆成多步 |

## Star Harness

`star-harness/*` 五个 operation 管的是**本机** Star Harness（`harness` 运行时）的安装、启停与工作区绑定。它们只对 Studio 宿主所有者开放，非所有者调用会直接拿到 `STAR_HARNESS_OWNER_REQUIRED`。

| 症状 | 错误码 | 原因 | 处理 |
| --- | --- | --- | --- |
| 点安装没反应 | `STAR_HARNESS_NOT_INSTALLED` | 还没装就点了启用或绑定（`src/host/services/star-harness.mjs:14`） | 先在插件页安装 Star Harness，再启用 |
| 安装报找不到 npm | `STAR_HARNESS_NPM_MISSING` | Studio 宿主进程找不到 `npm`（`star-harness-release.mjs:72`） | 装 Node.js 与 npm，确保宿主启动时的 `PATH` 里有 `npm` |
| 安装卡在下载 | `STAR_HARNESS_DOWNLOAD_FAILED` | 从 npm registry 下载失败（`star-harness-release.mjs:138`） | 检查网络与代理；确认版本号在 registry 上存在 |
| 安装报文件完整性失败 | `STAR_HARNESS_RELEASE_INVALID` | 版本号无效，或下载产物摘要不匹配（`star-harness-release.mjs:80`） | 重新安装；反复失败说明本地缓存损坏，删掉 Star Harness 状态目录后重装 |
| 安装后启动不起来 | `STAR_HARNESS_START_FAILED` | 子进程启动失败或协议握手超时（`star-harness-release.mjs:225`） | 看宿主日志里的子进程 stderr；确认端口与工作区目录可写 |
| 这份版本没被校验 | `STAR_HARNESS_RELEASE_UNREVIEWED` | 该版本没有当前 Studio 的校验记录（`star-harness-release.mjs:28`） | 先更新 Studio，再装与之匹配的版本 |
| 版本与 Studio 不兼容 | `STAR_HARNESS_INCOMPATIBLE` | 引擎协议版本、包名或能力集不匹配（`star-harness-release.mjs:168`） | 换成 Studio 校验过的版本；不要手改 `pins` |
| 选的版本不被接受 | `STAR_HARNESS_VERSION_UNSUPPORTED` | 既不是新版，也不是上次回退的那个版本（`star-harness.mjs:191`） | 选更新的版本，或回退到「上次使用的版本」 |
| 版本号格式被拒 | `STAR_HARNESS_INVALID_REQUEST` | 版本号不是三段 semver，或参数类型不对（`star-harness.mjs:13`） | 用 `x.y.z` 形式；从列表里选，不要手打 |
| 绑定工作区被拒 | `STAR_HARNESS_WORKSPACE_CONFLICT` | 目录与已有绑定、外部 Harness 或 Star Harness 状态目录重叠（`star-harness.mjs:71`） | 换一个不嵌套、不重叠的目录 |
| 绑了工作区却起不来 | `STAR_HARNESS_MODEL_CHANGED` | 工作区绑定的模型档案被改过（`star-harness.mjs:65`） | 解绑后重新绑定，选当前可用的模型档案 |
| 任务跑着改版本被拒 | `STAR_HARNESS_BUSY` | 有任务在运行，或有变更正在应用（`star-harness.mjs:11`） | 等当前任务结束或取消后再改；不要在运行中连续点 |
| 管理服务已关闭 | `STAR_HARNESS_CLOSED` | 宿主正在关闭，管理服务已释放（`star-harness.mjs:12`） | 重启 Studio 宿主 |
| 本地设置读不出来 | `STAR_HARNESS_CONFIG_INVALID` | `settings.json` 缺失、损坏或字段类型不对（`star-harness.mjs:41`） | 删掉 Star Harness 状态目录下的 `settings.json` 后重新绑定 |
| 提示没有权限 | `STAR_HARNESS_OWNER_REQUIRED` | 非所有者主体调用了 `star-harness/*`（`src/host/routes/http.mjs:65`） | 用 Studio 宿主所有者账号操作 |
| 当前部署不支持 | `STAR_HARNESS_UNSUPPORTED` | 该部署没有挂载本机 Star Harness 管理器（`src/host/routes/star-harness.mjs:6`） | 改用独立 Harness 服务；本机管理只存在于桌面端与源码运行 |

## 会话与历史

| 症状 | 错误码 | 原因 | 处理 |
| --- | --- | --- | --- |

| 审批状态读不到 | 无固定码 | 原生审批 RPC 失败（`src/client/dsh/native-approval.mjs`） | 按提示「刷新」后重新核对原生运行状态 |
