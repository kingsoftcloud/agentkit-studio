# 平台资源使用指南

## 1. 适用场景

出现以下任一情况时，先按本指南确认资源形态，再采取动作：

- 用户提到知识库、文档问答、资料检索；
- 用户提到长期记忆、之前说过/记住过什么；
- 任务匹配某个已绑定 Skill / Skill Space 中的说明或脚本；
- 需要调用已绑定的 MCP 工具、HTTP 工具或 AgentEngine 内置 Tool；
- 工具、技能、检索结果不符合预期，需要判断“是没绑定还是不可用”。

## 2. 总原则

1. **绑定 ≠ 工具**。绑定只表示资源属于当前 Agent，不代表它一定以可调用工具的形式出现。
2. 工具名、技能名、参数结构**只以本会话实际注册的内容为准**，不要凭记忆或常识猜名字（例如不要假设存在 `search_knowledge`、`query_memory`、`queryKnowledgeBase` 之类的工具）。
3. 知识库和长期记忆由 Host 在每轮自动检索并注入上下文，**模型不需要也无法直接调用它们的 API**。
4. 资源不可用或未注册时如实说明，不伪造调用、不伪造检索结果、不用临时重写的代码冒充平台绑定脚本。

## 3. 资源在会话中的三种形态

| 形态 | 在会话中如何出现 | 如何使用 |
| --- | --- | --- |
| 自动注入的上下文 | 系统/上下文里出现 `Knowledge binding contract`、`Memory binding contract` 或 `Relevant resources` 段落 | 直接当作本轮真实数据引用 |
| Skill 目录 | 会话的技能目录列出技能名与描述；正文按需加载 | 用 `skill` 工具按精确名称加载全文 |
| 工具清单 | 每个已注册工具的名称、描述、参数 schema 会交给模型 | 用原生工具调用，参数按 schema |

云端部署的 Agent 会以“以下内容由 AgentKit Studio 在本轮从当前 Agent 绑定的知识库、记忆库或 Skill Space 读取”这样的系统消息注入检索上下文，语义与本地一致。

## 4. 知识库

- Host 会以**当前用户消息**作为查询，对绑定知识库做语义检索（平台默认 TopK=5），并把命中的片段写入上下文，通常带 `Knowledge binding contract` 说明，片段形如 `Knowledge (文档名): 内容`。
- 你应只引用上下文中**真实出现**的片段，并尽量标注来源文档名；不要补写、扩写或假装召回了未出现的内容。
- 没有命中片段**不等于**知识库未绑定：它只说明本轮没有检索到相关内容。此时可以说明“本轮未检索到相关内容”，必要时建议用户调整问题或到知识库页面核对文档，但不要断言资源不存在。
- 不要自行构造知识库 HTTP 请求；会话没有向你提供对应地址和凭证。

## 5. 长期记忆

- 开启召回时，Host 每轮自动查询绑定记忆库并注入 `Memory binding contract` 段落，片段形如 `Memory: ...`。
- 写入由 Host 在回答结束后提交，策略由平台配置决定：
  - `candidate`：每轮正常完成后自动提交本轮内容；
  - `explicit_only`：只有用户明确表达“记住/保存到记忆库”时才提交。
- 模型看不到独立的记忆工具或写入回执，**不要声称“已保存/已记住”是已验证事实**。需要确认时，说明平台会在本轮结束后写入，并建议用户到记忆库页面核对。
- 如果上下文明确写了“跨会话长期记忆已关闭”，说明本轮既不会召回也不会写入，不能据此声称有记忆能力。
- 记忆召回内容与知识库检索片段是不同来源，不要互相替代或混为一谈。

## 6. Skill 与 Skill Space

- 已绑定的 Skill / Skill Space 会出现在会话技能目录中，通常由 Host 物化成本地资源目录，目录里有 `SKILL.md` 和随技能提供的脚本、引用文件。
- 需要正文时，调用会话中的 `skill` 工具，参数 `name` 使用目录里的**精确技能名**；工具返回的技能正文会附带 `Base directory for this skill: <资源目录>`。
- 技能正文里的相对路径（脚本、模板、引用文件）**相对于该资源目录**，不是当前工作区；执行前先拼出完整路径。
- 执行已绑定的脚本时优先直接运行原脚本，不要用临时重写的代码替代；文件或依赖缺失时如实报告缺失项。
- 需要执行脚本或读取资源文件时，使用会话提供的 shell 工具（POSIX 为 `bash`，Windows 为 `pwsh`）；如果会话没有这类工具，不要假设可以自行执行本地脚本。
- 如果会话没有 `skill` 工具，或技能目录中没有目标技能，就视为未绑定/未加载；不要假装已读取技能内容。

## 7. MCP / HTTP 工具

- 绑定 MCP 后，Host 会以 MCP server `tools/list` 返回的**原始工具名**注册为会话工具，描述和参数 schema 也来自该返回。工具名可能带前缀或风格不一，以会话工具清单为准。
- 调用方式就是普通原生工具调用；参数严格按该工具的 schema 传入。
- 不要在模型侧自行拼接 MCP/HTTP endpoint、请求头或鉴权信息，也不要用 curl 之类命令绕过已注册工具去访问平台内部接口。
- MCP 发现失败时，上下文可能带有 `MCP <资源> 当前不可用：...` 这类警告（`Bound resource warnings`）。此时应说明该 MCP 暂时不可用并建议重试或检查绑定，而不是假设工具存在或编造调用结果。
- 多个绑定暴露同名工具时平台会拒绝注册（工具名冲突）。遇到“同名工具”类报错，应提示用户检查绑定，而不是改名硬调。

## 8. AgentEngine 内置 Tool

- 绑定在 Agent 的 `tools` 中的 AgentEngine 内置 Tool 会以契约里的名称注册为会话工具，由 Host 侧的 Python toolset 执行。
- 工作区范围、读取/修改状态与审批策略由平台约束；按工具描述使用，不要试图绕过工作区限制或审批流程。
- 若内置 Tool 没有出现在会话工具清单，说明它未绑定或宿主目录暂时不可用；照实说明即可。

## 9. 模型凭证与端点

- 模型凭证、网关地址、数据库连接等由平台注入，只在 Host 内部使用。
- 不要向用户索取、回显、记录或猜测任何 API Key、Token、endpoint；也不要为了“绕过限制”自行发起模型或平台 API 请求。

## 10. 资源不可用时如何上报

按下面顺序判断，并给出具体、可执行的说明：

1. **工具不在会话工具清单**：说明“当前会话未注册该工具，可能未绑定或该资源不可用”，不要模拟调用。
2. **工具调用返回错误**：原样保留错误码和要点，例如 `BOUND_TOOL_NOT_FOUND`、`MCP_RESOURCE_NOT_BOUND`、`TOOL_ADAPTER_MISSING`、`SKILL_NOT_INSTALLED`、`SKILL_MANIFEST_MISSING`、`MEMORY_SERVICE_UNAVAILABLE` 等（以实际返回为准），并建议重新选择/绑定资源。
3. **知识库或记忆无召回**：只说明本轮没有检索到，不断言资源不存在，也不编造召回内容。
4. **会话级资源恢复失败**（如 `STUDIO_PRESET_RESOURCES_UNAVAILABLE`）：说明该会话的资源快照不可用，需要重新选择 Agent 或重新打开应用，不要在残缺资源上继续假装执行。
5. **不要降级成猜测**：不猜测工具名、不猜测接口字段、不用 shell 直接访问平台后端、不虚构结果；需要用户操作时给出明确下一步。

本指南只描述 Studio Host 已经实现的机制。某个能力在会话中没有对应工具、目录项或注入内容时，就视为本会话未启用，不要假设它一定存在。
